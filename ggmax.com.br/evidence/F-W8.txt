# F-W8 — PII Leak CRÍTICO via /api/user-order-reviews (API antiga ggmax.com.br sem auth)

## Data: 2026-09-05T00:28Z
## Host: ggmax.com.br (atrás de Cloudflare, bypass via Playwright + Tor)
## Severidade: CRÍTICA
## CVSS: 9.1 (AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N)

## Descrição

O endpoint `/api/user-order-reviews` da API legada do ggmax.com.br (PHP/Laravel)
retorna as 8 reviews mais recentes de TODOS os usuários SEM AUTENTICAÇÃO.
Cada review expõe:
- Dados do pedido (order_id, anúncio, título do produto, slug, categoria)
- Dados do comprador (user_id, username, avatar, date_last_access, date_created)
- Dados do vendedor (target_user_id, user_id do anúncio)
- Mensagem da review (feedback text)
- Tipo (buyer/seller), review_type (positive/negative), status

## Reprodução

```bash
# Após bypass Cloudflare (ver F-W7), navegar ao endpoint:
# https://ggmax.com.br/api/user-order-reviews
# Retorna 200 com 8 reviews (JSON, ~32KB)
```

## Pagination

- Endpoint retorna sempre 8 reviews (mais recentes), independente de params
  (`?page=`, `?per_page=`, `?limit=`, `?offset=` — todos ignorados)
- As 8 reviews são as MAIS RECENTES (timestamp ~2026-09-04 21:30)
- Dados mudam a cada chamada (reviews novas chegam em tempo real)
- Não há paginação para reviews antigas (apenas as 8 mais recentes)

## Impacto

- Vazamento CONTÍNUO de dados de compradores e vendedores (reviews em tempo real)
- Usernames, user IDs, avatares, datas de último acesso e criação de conta
- Títulos de anúncios (produtos vendidos) — intelligence de mercado
- Conexão comprador↔vendedor↔produto (grafo de transações)
- `date_last_access` permite saber quais usuários estão ativos agora
- Combina com F-W7 (accounts/search) e F-W9 (inspect) para perfil completo

## Recomendação

1. **DESATIVAR** o endpoint `/api/user-order-reviews` sem auth (API legada).
2. Exigir autenticação e escopar reviews ao usuário autenticado.
3. Remover `date_last_access`, `is_password_change_required` de respostas públicas.
4. Migrar todo o tráfego da API legada para a nova API (api.keyz.gg/NestJS).

## Notas

- A API legada usa formato `{"success":true,"data":[...]}` (PHP/Laravel)
- A nova API (NestJS) usa `{"message":...,"statusCode":...}` — formato diferente
- Ambas coexistem: API legada em ggmax.com.br/api/*, nova em api.keyz.gg/*
- A API legada NÃO está documentada no wayback como "deprecated" — parece
  ter sido esquecida durante a migração para keyz.gg
