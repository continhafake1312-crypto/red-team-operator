## Contexto
Meilisearch dashboard exposto em `search.keyz.gg` (acessível via bypass CF: `Host: search.keyz.gg`
no origin 104.238.205.118). Enum (Fase 5) confirmou:
- `/health` → 200 público (`{"status":"available"}`)
- `/indexes`, `/stats`, `/version` → 401 "missing_authorization_header" (requer Bearer)
- API key NÃO está no client-side (server-side only — `MEILI_MASTER_KEY` env no server)

Creds.txt (fase 7) já testou 5 chaves comuns (masterKey/meili/default/test/secret) → 403.
Coordenador (§19) pediu brute force mais exaustivo.

## Hipótese
Se a master key do Meilisearch for fraca (default, ou derivada do engagement), brute force
com wordlist focada pode encontrá-la → acesso a /indexes → dump de PII (se houver index de
usuários/pedidos).

## Análise
- **612 candidates** cobrindo defaults Meilisearch, engagement terms (keyz/ggmax/keyzgg/
  thyoity/coolify), leaked-secrets reusadas, mutations sistemáticas — TODAS retornaram 403.
- A master key do Meilisearch NÃO é:
  - Um default fraco (masterKey, meili, default, test, secret, admin, password, etc.)
  - Derivada do engagement (keyz, ggmax, keyzgg, thyoity, + patterns)
  - Uma secret vazada reusada (Soketi key, Mercado Pago key, buildId, maintenancePassword)
  - Uma mutação comum (base + dígitos/símbolos/anos/sufixos)
- A master key é **forte/aleatória** (provavelmente 32+ bytes hex/gerada por `openssl rand`).
  Com 612 candidates em 17 min via Tor, e a key sendo aleatória, brute force é inviável
  (espaço de 16 bytes = 2^128).
- Não há rate limit observado no Meilisearch (mas isso não ajuda — o problema é o espaço
  de busca, não a taxa).

## Impacto
NENHUM. Meilisearch API key NÃO é brute-forceable com wordlist focada. Sem acesso aos
indexes/documents. O dashboard exposto (F-A3) permanece info-disclosure visual, mas NÃO
permite dump de dados sem a key.

## Recomendação
1. **Manter master key forte/aleatória** (já está — 32+ bytes). NÃO usar defaults ou
   keys derivadas do business.
2. **Rotacionar master key periodicamente** e armazenar em secret manager (não em env
   hard-coded).
3. **Restringir acesso ao dashboard** search.keyz.gg via WAF/IP allowlist (hoje exposto
   no origin sem WAF — F-A3).
4. **Desabilitar o dashboard** Meilisearch em produção (`MEILI_NO_ANALYTICS=true` +
   `--no-analytics`; o dashboard mini-dashboard é exposto por default).
5. Considerar API keys scoped (search-only key pública para o client, admin key privada)
   em vez de master key para tudo.
