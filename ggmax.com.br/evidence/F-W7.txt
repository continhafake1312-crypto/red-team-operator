# F-W7 — PII Leak CRÍTICO via /api/accounts/search (API antiga ggmax.com.br sem auth)

## Data: 2026-09-05T00:28Z
## Host: ggmax.com.br (atrás de Cloudflare, bypass via Playwright + Tor)
## Severidade: CRÍTICA
## CVSS: 9.3 (AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N)

## Descrição

A API LEGADO do ggmax.com.br (PHP/Laravel, formato `{"success":...,"data":...}`)
ainda está ATIVA e expõe dados de contas do marketplace SEM AUTENTICAÇÃO.
O endpoint `/api/accounts/search?q={username}` retorna dados completos de
contas de vendedores (marketplace listings) incluindo:
- ID da conta, nome da conta, categoria, data de criação
- Records com: created_by (user ID), user_id (owner), external_email (mascarado),
  external_cpf (mascarado), public_note, datas, status
- User object COMPLETO: id, avatar, username, type, date_last_access (último login!),
  date_created (data de criação da conta), is_vip, is_on_vacation,
  is_password_change_required, cpf (mascarado)
- Category object completo (nome, slug, SEO, configurações)

## Confirmação F-P3 (wayback) — LIVE e EXPLOITÁVEL

O wayback (Fase 2) encontrou `https://ggmax.com.br/api/accounts/search?q=02952810575`
como PII leak potencial. Confirmamos que o endpoint ESTÁ VIVO e retorna dados
de contas quando o query match um username de vendedor.

## Notas importantes

1. O endpoint pesquisa contas do MARKETPLACE (listings de vendedores), não
   contas de usuário. Usernames de COMPRADORES (Israel05, Kinde) não match.
2. O query mínimo é 2 caracteres.
3. Email/CPF são PARCIALMENTE mascarados (mas a estrutura existe no response).
4. O mascaramento pode ser bypassável com auth ou params diferentes (não testado
   a fundo — page.request com headers causa 403 CF).
5. `date_last_access` (último login) NÃO é mascarado — útil para targeting.
6. O SQLi foi testado e DESCARTADO (respostas parametrizadas/idênticas).

## Impacto

- Enumeração de vendedores (qualquer username → dados da conta)
- Vazamento de user IDs, nomes de contas, avatares, categorias
- Vazamento de `date_last_access` (último login) — info de atividade
- Vazamento de `date_created` (data de criação da conta) — histórico
- Vazamento de `public_note` (notas internas dos vendedores)
- Email/CPF parcialmente mascarados mas estrutura existe (potencial bypass)
- Combina com F-W8/F-W9 para construir perfil completo de vendedores

## Recomendação

1. **DESATIVAR** a API legada do ggmax.com.br (PHP/Laravel) — a nova API
   (api.keyz.gg/NestJS) substituiu-a mas a antiga permanece ativa.
2. Se a API legada precisa continuar (compatibilidade), exigir AUTENTICAÇÃO
   em TODOS os endpoints /api/accounts/*, /api/users/*, /api/user-order-reviews.
3. Aplicar rate limiting no /api/accounts/search (prevenir enumeração).
4. Remover `date_last_access` de respostas não-autenticadas.
5. Revisar todos os endpoints /api/* legados para auth e mascaramento.
