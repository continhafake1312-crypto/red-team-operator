## CVEs históricos a verificar (não-destrutivo)

### Elementor 4.2.3
- **CVE-2024-2771** (path traversal → RCE) — afeta Elementor ≤ 3.21.x
  (mas renomeado para 4.x em 2025+; verificar backport)
- **CVE-2024-21043** (path traversal)
- **CVE-2024-20656** (auth bypass)
- **CVE-2023-XXXX** (XSS via template)
- CVE em **template builder** (`/wp-json/elementor/v1/templates`)
- CVE em **onboarding endpoint** (`/wp-json/elementor/v1/onboarding`)

### UpdraftPlus 1.26.6
- **CVE-2023-32961** (CSRF → backup download) — afeta < 1.23.3
- **CVE-2023-XXXX** (backup restoration RCE) — afeta < 1.24
- **CVE-2024-XXXX** (path traversal em restore) — afeta < 2.x
- Vulnerabilidades no diretório `/wp-content/updraft/` (auth bypass)

## Vetores

1. **Elementor RCE via template import/upload** — exploit público existe
   para versões antigas; vamos testar via subagente `exploit`.
2. **UpdraftPlus backup download** — diretório `updraft/` retorna 403
   (Wordfence/.htaccess) mas pode ter bypass via método conhecido.
3. **WordFence bypass** — versão 9.0.0 pode ter WAF bypass em certos
   payloads (research de WAF evasion).

## Impacto

- **CRÍTICO** se UpdraftPlus RCE funciona → acesso direto por backup
  restoration com webshell dentro do backup.
- **ALTO** se Elementor RCE funciona → acesso via template import.
- **MÉDIO** se apenas XSS → escalation via admin click.

## Recomendação

1. **Delegar `cve` specialist** para mapear todos os CVEs exatos por
   versão + buscar PoCs.
2. **Delegar `exploit` specialist** para testar PoCs em ambiente não-
   destrutivo (criar backup primeiro, testar, restaurar).
3. **Verificar `elementor/v1/onboarding`** endpoint — pode ter auth
   bypass conhecido.
