## Interpretação
A chave Anon do Supabase é tecnicamente "pública" (destinada ao client-side), mas sua exposição em bundle JS permite:
- Acesso à API REST do Supabase (embora com RLS configurado)
- Conhecimento do Project ID (`ahfviyykpaljzxcmdyfh`)
- Identificação da infraestrutura de backend

## Impacto
- **Baixo direto**: anon key é destinada ao uso público, RLS deve proteger as tabelas
- **Médio indireto**: permite ataques direcionados ao Supabase (tentativas de bypass RLS, enumeração de schemas)

## Recomendação
- A anon key é necessária no client-side, portanto não é possível removê-la completamente
- Garantir que as RLS policies estejam rigorosamente configuradas
- Usar Supabase Service Role key apenas em server-side (já é o caso)
- Considerar ofuscação do bundle JS para dificultar extração automatizada
