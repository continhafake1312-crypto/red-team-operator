# F-008 Supabase Session JWT — Acesso Ampliado via REST API

**Alvo:** ahfviyykpaljzxcmdyfh.supabase.co (via legasforn.com.br)
**Severidade:** Média
**Timestamp:** 2026-08-24T18:25:00Z

## Reprodução
O cookie de sessão `sb-*-auth-token` (armazenado em base64) contém um JWT do Supabase Auth. Este JWT pode ser extraído e usado para acessar a REST API do Supabase diretamente, bypassando a camada de API da LegasForn.

### Extração do JWT
O cookie de sessão contém um JSON base64 com `access_token` (JWT). Extraído via:
```bash
cat session_cookies.txt | sed 's/.*sb-auth-token=base64-//' | base64 -d | jq -r '.access_token'
```

### Acesso às tabelas do Supabase
Com o JWT + anon_key, é possível consultar diretamente `https://{project}.supabase.co/rest/v1/{tables}`.

**Tabelas acessíveis (200/206):**
| Tabela | Registros | Conteúdo |
|--------|-----------|----------|
| `profiles` | 1 (próprio) | Perfil do usuário autenticado |
| `api_keys` | 2 (próprias) | Chaves de API com scopes, prefixo, hash, status |
| `api_audit_log` | 8 (próprios) | Logs de auditoria: ação, IP, status, detalhes do erro |
| `nfa_products` | 9 | Catálogo de produtos NFA (público) |
| `user_wallets` | 0 | Carteira do usuário |
| `wallet_transactions` | 0 | Transações da carteira |
| `orders` | 0 | Pedidos do usuário |
| `referrals` | 0 | Indicações |
| `tickets` | 0 | Tickets de suporte |
| `reviews` | 0 | Reviews |
| `security_logs` | 0 | Logs de segurança |
| `fraud_events` | 0 | Eventos de fraude |

**Tabelas bloqueadas por RLS:**
| Tabela | Motivo |
|--------|--------|
| `coupons` | `permission denied for table coupons` (authenticated role sem SELECT) |

### Exemplo de resposta
```json
// /rest/v1/profiles?select=id,email,display_name,is_admin,wallet_balance,vip_level
[{
  "id": "d9724f56-...",
  "email": "pentest_webapp_...@mailinator.com",
  "display_name": "pentest_webapp_...",
  "is_admin": false,
  "wallet_balance": 0.0,
  "vip_level": 1
}]
```

## Interpretação
O Supabase utiliza RLS (Row Level Security) que corretamente escopa os dados ao usuário autenticado. Entretanto:
1. O session JWT fica exposto no cookie do navegador e pode ser extraído por XSS ou pela análise do cookie armazenado
2. Acesso direto ao Supabase REST expande o attack surface significativamente
3. Tabelas como `api_audit_log` expõem dados de auditoria que não deveriam ser acessíveis via API REST direta
4. Qualquer falha futura de RLS em uma tabela exporia todos os dados

## Impacto
- **Médio**: O acesso direto ao Supabase REST permite que um atacante explore futuras falhas de RLS
- **Médio**: A tabela `api_audit_log` expõe IP, key_id e detalhes de ações do usuário
- **Baixo (atual)**: RLS está corretamente configurado para a maioria das tabelas

## Recomendação
1. Restringir acesso ao Supabase REST API apenas para o service_role (server-side), não para usuários autenticados
2. Implementar uma API proxy que filtre e limite os endpoints do Supabase expostos
3. Monitorar acessos diretos ao Supabase REST via logs de auditoria
4. Garantir que RLS policies sejam revisadas periodicamente para todas as tabelas
