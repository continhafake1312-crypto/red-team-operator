# F-009 Tabela api_audit_log Exposta via Supabase REST

**Alvo:** ahfviyykpaljzxcmdyfh.supabase.co (via session JWT)
**Severidade:** Média
**Timestamp:** 2026-08-24T18:25:00Z

## Reprodução
A tabela `api_audit_log` no Supabase é acessível via REST API para qualquer usuário autenticado. Através do session JWT extraído do cookie, é possível consultar todos os registros de auditoria do usuário.

```bash
curl -s "https://ahfviyykpaljzxcmdyfh.supabase.co/rest/v1/api_audit_log?select=*&limit=10" \
  -H "apikey: {anon_key}" \
  -H "Authorization: Bearer {session_jwt}"
```

### Dados expostos
```json
[{
  "id": "dac53c22-...",
  "key_id": "a62ecdc5-...",
  "user_id": "d9724f56-...",
  "action": "purchase.failed",
  "status": "error",
  "ip": "56.125.111.53",
  "detail": {"code": "insufficient_balance", "game": "fortnite"},
  "created_at": "2026-08-24T18:10:28.232535+00:00"
}]
```

### Campos expostos
- `id`: UUID do registro
- `key_id`: UUID da chave de API usada
- `user_id`: UUID do usuário
- `action`: Nome da ação (ex: purchase.failed, coupon.created, etc.)
- `status`: Status (success, error, etc.)
- `ip`: Endereço IP do cliente
- `detail`: JSON com detalhes adicionais (código do erro, parâmetros da ação)
- `created_at`: Timestamp da ação

## Interpretação
Embora a tabela seja escopada por RLS para mostrar apenas registros do próprio usuário, a exposição de logs de auditoria detalhados via REST API direta não é uma prática recomendada. Idealmente, logs de auditoria deveriam ser acessíveis apenas via service_role key (server-side).

## Impacto
- **Médio**: Um atacante com acesso ao session JWT (via XSS ou roubo de cookie) pode:
  - Mapear padrões de uso da API
  - Identificar endpoints vulneráveis (ex: ações com status "error")
  - Coletar IPs e timestamps de ações
  - Analisar detalhes de erros que podem conter informações sensíveis
- **Alto potencial**: Se uma futura falha de RLS expuser registros de outros usuários, o impacto seria severo

## Recomendação
1. Remover a permissão de SELECT na tabela `api_audit_log` para a role `authenticated`
2. Implementar acesso a logs apenas via endpoints da API LegasForn (não diretamente via Supabase REST)
3. Revisar todas as RLS policies para garantir que apenas o mínimo necessário seja exposto
