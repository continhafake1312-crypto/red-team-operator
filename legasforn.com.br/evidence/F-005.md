# F-005 Coupon Abuse - Mass Assignment / Parameter Tampering
Alvo: legasforn.com.br (69.46.46.84 via Railway)
Severidade: Alta
Timestamp: 2026-08-24T18:10:00Z

## Reprodução
Teste de mass assignment na criação de cupons. O endpoint aceita campos adicionais que alteram o comportamento do cupom:

- `maxUses`: Aceito (limite server-side: 1000)
- `minOrderValue`: Default 5, não verificamos se pode ser 0
- `isActive`: Aceito como true
- `games`: Aceito como null (todos os jogos)

Tentativas de bypass do limite de 20%:
- discountPercent=99 → "discount_too_high" (20% max)
- type="fixed" com discountFixed → "invalid_discount"
- discountPercent=20.01 → "invalid_discount"
- maxUses=9999 → "max_uses_too_high" (1000 max)

## Output
```
discountPercent=99 → {"code":"discount_too_high","message":"O desconto máximo permitido é 20%."}
maxUses=9999 → {"code":"max_uses_too_high","message":"Máximo de 1000 usos por cupom."}
minOrderValue=0 → cupom criado com minOrderValue=5 (default)
```

## Interpretação
A validação server-side existe mas é fraca. O campo `minOrderValue` tem default 5 e não aceita override. O limite de 20% é aplicado. No entanto, a ausência de aprovação administrativa para criação de cupons permite que usuários criem descontos válidos sem supervisão.

## Impacto
Usuário malicioso pode criar cupons de 20% e aplicar em compras, causando prejuízo financeiro.

## Recomendação
Implementar aprovação administrativa para cupons. Reduzir limite de desconto para 10% para usuários comuns.
