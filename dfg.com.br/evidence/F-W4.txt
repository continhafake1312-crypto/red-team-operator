# webapp finding | suppliers.dfg.com.br (161.97.106.115) + antigo.dfg.com.br (161.97.106.115)

- https://161.97.106.115/offers.aspx (Host: suppliers.dfg.com.br OR Host: antigo.dfg.com.br)

- Direct origin IP (no Cloudflare WAF), unauthenticated.

## Description
The legacy DFGames Suppliers-AZR application has ASP.NET detailed errors enabled
(`customErrors mode="Off"` / `mode="RemoteOnly"` ineffective against direct origin). Requesting
`/offers.aspx` without a valid session returns HTTP 500 with a FULL stack trace that discloses:
- The absolute source path on the server: `C:\DFGames\Old\Suppliers-AZR\Suppliers-AZR\offers.aspx.cs`
- The exact line number: `line 17`
- The code-behind class and method: `page_offers.Page_Load(Object sender, EventArgs e)`
- The exception type: `ArgumentNullException: Value cannot be null.`
- The application folder structure (`Old\Suppliers-AZR\Suppliers-AZR\` → legacy/old + Azure-origin hint "AZR")

This confirms the app is a legacy ("Old") ASP.NET WebForms codebase (suppliers marketplace) and
leaks internal directory layout, which aids targeted attacks (path traversal, ViewState
machineKey extraction, deployment-config discovery, LFI/`web.config` reads via known paths).

`/News.aspx` (also 500) additionally discloses the ObjectDataSource name (`odsNews`), the data
method (`GetNews`) and parameter (`culture`) — a data-layer hint for parameter tampering.

## Impact
- Internal source path disclosure (`C:\DFGames\Old\Suppliers-AZR\...`) enables targeted file-read
  attempts (e.g., `web.config` at `C:\DFGames\Old\Suppliers-AZR\Suppliers-AZR\web.config` for
  machineKey/connstrings) via any LFI/path-traversal vector (CVE-2015-4670 AjaxFileUpload, or a
  future ViewState machineKey leak). The path also confirms the codebase is a legacy ("Old")
  port of an Azure-hosted version ("AZR").
- Class/method/line leak aids reverse engineering of the auth/payment logic (e.g., offers.aspx
  page_offers.Page_Load at line 17 parses a numeric session param → null ref → confirms a
  nullable int parse, matching the requests-xml prefix-match behaviour observed in F-W1).
- "Old\Suppliers-AZR" folder implies a current/new version exists elsewhere (potential staging).
- Combined with the leaked contact (salesmgr@dfgames.com, phone 61-83036060) this is useful OSINT.

## Recommendation
- Set `customErrors mode="On"` (or `RemoteOnly` with the origin not reachable directly) in Web.config
  and configure a generic error page; disable `compilation debug="true"`.
- Validate session/params before parsing (handle null with a redirect to login / default page).
- Remove dev/test pages (`teste.aspx`) and stale endpoints.
- Restrict direct origin access (place behind Cloudflare / IP allowlist) so detailed errors are
  not reachable externally.
