# F-EXP-06 — Mailcow (77.237.241.198) /admin/ credential stuffing: no valid creds (default rejected)
> Target: 77.237.241.198 (Host: mail.astarium.com) — Mailcow admin panel, nginx, no WAF
> Vector: /admin/ login (login_user / pass_user / csrf_token + session cookie)
> Phase: exploit (validation) — NON-DESTRUCTIVE credential stuffing (rate-limited)
> Timestamp: 2026-09-05T00:45Z–01:01Z (ISO8601 UTC) [key users (admin) fully covered; remaining users in progress]
> Via: Tor SOCKS5

## Mechanism
Mailcow /admin/ login: GET /admin/ → extract csrf_token (hex64 embedded in injected hidden input
`value="HEX64">').attr('name','csrf_token'`) + session cookie → POST /admin/ with
login_user/pass_user/csrf_token → GET /admin/ → success if login form (login_user/pass_user inputs)
is gone and page changed. Baseline: `admin:moohoo` → pre=39555, post_get=39555, form_present=True
(still on login page) → REJECTED (re-confirms default creds changed).

## Conclusion
No valid credentials found on Mailcow /admin/ in the targeted set. The key username `admin` (most
likely, since Mailcow default admin username is "admin" with a changed password) was tested against
31 targeted passwords (moohoo + company/year patterns + common) with no match. Default creds changed
(confirmed). No Mailcow version obtained (requires auth — not achieved).

## Impact
No Mailcow admin access. Without admin, the Mailcow/SOGo CVE chain (CVE-2025-53909 SSTI→RCE,
CVE-2026-40871 SQLi) cannot be assessed (version unknown, requires auth).

## Recommendation (defender)
- Default admin/moohoo already changed (good). Keep strong unique admin password + MFA if available.
- Add rate-limiting/alerting on /admin/ login.
- Keep /admin/ behind a restricted path or VPN if possible (currently internet-exposed, no WAF).

## Recommendation (red team / next steps)
- If a Mailcow admin cred is obtained (breach data), test login → extract version → assess CVE chain.
- SOGo webmail (/SOGo/) with mailbox creds (if any obtained via SmarterMail) is an alternate vector.
