# F-EXP-05 — Suppliers (161.97.106.115) /login.aspx credential stuffing: no valid creds
> Target: 161.97.106.115 (Host: suppliers.dfg.com.br) — DFGames Suppliers Central, ASP.NET WebForms
> Vector: /login.aspx form (ctl00$txtEmail / ctl00$txtPassword + ViewState/EventValidation), NO CAPTCHA on login
> Phase: exploit (validation) — NON-DESTRUCTIVE credential stuffing (rate-limited)
> Timestamp: 2026-09-05T00:48Z–01:00Z (ISO8601 UTC)
> Via: Tor SOCKS5, fresh session per attempt (ViewState+EventValidation re-fetched each time)

## Mechanism
Standard ASP.NET WebForms login. Per attempt: GET /login.aspx → extract __VIEWSTATE /
__VIEWSTATEGENERATOR / __EVENTVALIDATION + session cookie → POST with __EVENTTARGET=ctl00$signInBUTTON,
the form fields, and the ViewState/EventValidation. **No CAPTCHA on login** (only register.aspx has
ImgValidator CAPTCHA). Success detection: 302 redirect away from login OR authenticated markers
(logout/sair/myoffers/newsale/balance) without the login form present.

## Note on parallel webapp finding (F-W7)
The webapp phase (separate) CONFIRMED open supplier registration (register.aspx + 2Captcha) and obtained
an AUTHENTICATED supplier session (DFGSuppliers cookie) via 2 test accounts. That is a LOWER-privilege
foothold (a freshly-registered supplier account). This credential stuffing targeted EXISTING / higher-
privilege accounts (owner/admin emails) and found no valid creds. The webapp foothold stands; this
stuffing adds that no existing-account cred was recoverable via the targeted common-password set.

## Conclusion
No valid credentials found on suppliers /login.aspx in the targeted set (108 attempts, 9 users × 12
common passwords). Login has no CAPTCHA (bruteable in principle) but the targeted passwords did not
match. No rate-limiting observed (unlike SmarterMail) — a larger/breach-correlated wordlist could be
attempted, but payoff is now lower (a low-priv supplier session already exists via open registration).

## Recommendation
- Add rate-limiting / CAPTCHA / account lockout on /login.aspx (currently none observed).
- Enforce strong passwords for supplier accounts; rotate salesmgr@dfgames.com and admin emails.
- The open registration (F-W7) remains the bigger issue (anyone can create a supplier account).
