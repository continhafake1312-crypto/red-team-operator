# F-004 CORS Wildcard Permitindo Qualquer Origem

**Alvo:** apsv-iptv.duckdns.org (56.125.111.53 — AWS)
**Severidade:** Média
**Timestamp:** 2026-08-22T22:00:00Z
**Tipo:** Security Misconfiguration

## Descoberta
O header `Access-Control-Allow-Origin: *` permite que qualquer site faça requisições cross-origin à API.

## Reprodução
```bash
curl -s -I 'https://apsv-iptv.duckdns.org/api/health' | grep -i access-control
```

## Output
```
Access-Control-Allow-Origin: *
Access-Control-Allow-Methods: GET, POST, PUT, DELETE, OPTIONS
Access-Control-Allow-Headers: Content-Type, Authorization
```

## Impacto
- Qualquer site malicioso pode fazer requisições à API autenticada se o usuário estiver logado
- Possível CSRF + CORS combinado para exfiltração de dados
- Facilita ataques de phishing com origens arbitrárias

## Recomendação
- Restringir CORS a origens conhecidas (https://apsv-iptv.duckdns.org, https://telaviva.com.br)
- Nunca usar `Access-Control-Allow-Origin: *` em APIs com autenticação baseada em cookie/sessão

## Próximo passo
- Verificar se há cookies HttpOnly + SameSite configurados
- Testar CSRF nos endpoints sensíveis
