# F-011 Host Header Injection entre Subdomínios
Alvo: integration.focusconcursos.com.br (Laravel API)
Severidade: Baixa
Timestamp: 2026-08-22T01:55:00Z

## Reprodução
curl -H "Host: admin.focusconcursos.com.br" https://integration.focusconcursos.com.br/
→ Resposta: 302 redirect para admin.focusconcursos.com.br/login
  (veio da app admin hospedada no mesmo IP)

curl -H "Host: lms.focusconcursos.com.br" https://integration.focusconcursos.com.br/
→ Resposta: 302 redirect para lms.focusconcursos.com.br/login
  (veio da app LMS)

curl -H "Host: payment.focusconcursos.com.br" https://integration.focusconcursos.com.br/
→ Resposta: 200 `{"status":"ok"}` (mesma app que integration)

## Output
Host header injection demonstra que todos os 4 hosts (integration, admin, lms, payment)
estão no mesmo servidor Nginx (54.152.191.245) com virtual hosting.

## Interpretação
- Mesmo IP (54.152.191.245) serve múltiplos subdomínios via virtual hosting
- Nginx roteia baseado no Host header
- Integration e payment parecem ser a mesma aplicação (mesmo health check)
- Admin e LMS são apps separadas

## Impacto
- Baixo: sem impacto direto de segurança
- Potencial para ataques SSRF se houver funcionalidade de fetch em um dos apps
- Confusão de cache em proxies reversos

## Recomendação
- Verificar se o comportamento é intencional (virtual hosting)
- Garantir que apps em ambiente compartilhado tenham isolamento adequado
- Validar Host header nas aplicações
