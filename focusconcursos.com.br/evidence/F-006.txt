# F-006 Laravel — Sanctum Ativo, APP_DEBUG=false
Alvo: integration.focusconcursos.com.br (Laravel/PHP/Nginx)
Severidade: Média
Timestamp: 2026-08-22T01:30:00Z

## Reprodução
- GET / → 200 `{"status":"ok"}` com cookies XSRF-TOKEN e laravel_session
- GET /sanctum/csrf-cookie → 204 (Laravel Sanctum confirmado)
- GET /_debugbar → 404 (debugbar não instalado)
- GET /_ignition/health-check → 404 (Ignition não instalado)
- GET /_debugbar/open → 404
- GET /clockwork → 404
- GET /telescope → 404
- GET /routes → 404
- GET /.env → 404 (retorna HTML 404 do Laravel, .env não exposto)
- POST /graphql → `{"exception":"Symfony\\Component\\HttpKernel\\Exception\\NotFoundHttpException","message":"Not Found","trace":null}` (APP_DEBUG=false confirmado)

## Output
- Apenas o endpoint raiz (GET /) é funcional, retornando `{"status":"ok"}`
- Sanctum CSRF cookie endpoint (GET /sanctum/csrf-cookie) responde 204
- POST para qualquer rota inexistente retorna JSON com NotFoundHttpException e trace=null
- Estáticos servidos: /favicon.ico, /robots.txt
- Arquivos expostos: /.htaccess, /web.config (regras de rewrite do Laravel)

## Interpretação
- APP_DEBUG=false (trace=null nas exceções serializadas)
- Laravel Sanctum configurado (proteção CSRF via cookies)
- API mínima — apenas health check exposto publicamente
- Debug packages (_debugbar, _ignition, clockwork, telescope) NÃO instalados

## Impacto
- Baixo risco individual — sem endpoints de debug acessíveis
- Porém, Sanctum sugere que existem rotas autenticadas em produção
- APP_KEY não exposta, env não vazado
- Ataques via CVE-2021-3129 (Ignition) não possíveis

## Recomendação
- Manter APP_DEBUG=false em produção (já configurado)
- Remover arquivos .htaccess e web.config do diretório público
- Garantir que rotas autenticadas usem auth middleware
