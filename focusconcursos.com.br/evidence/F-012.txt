# F-012 CKFinder 3 Exposto sem Autenticação — Leitura Irrestrita
Alvo: admin.focusconcursos.com.br (Nginx, Laravel)
Severidade: Alta
Timestamp: 2026-08-22T02:10:00Z

## Descrição
CKFinder 3 (v3.x) está ativo em `/ckfinder/connector` e `/ckfinder/browser` sem qualquer autenticação para operações de leitura (GET). Qualquer pessoa pode listar arquivos, pastas e obter configuração completa do backend S3.

### 5. Upload Bloqueado (Escrita Protegida)
```
POST /ckfinder/connector?command=FileUpload&type=Arquivos&currentFolder=/
  -F "upload=@file.txt"
→ 400 {"error":{"number":109,"message":"Invalid request."}}

PUT https://s3-sa-east-1.amazonaws.com/focus-library/5333f320-a79d-11e7-be81-833fcc7d70fc/Editor/arquivos/test.txt
→ 403 AccessDenied
```

## Interpretação
CKFinder 3 está configurado com:
- Autenticação apenas para operações de escrita (POST)
- ACL=1023 (full permissions) mas o backend blocking POST
- Backend S3 na AWS (sa-east-1) com bucket `focus-library`
- CKEditor 4.12.1 configurado com CKFinder como filebrowser
- Sessão vazia ("s":"") indica que não há verificação de sessão ativa
- "uploadCheckImages":false — server-side image validation desligada

## Impacto
- ALTO: Vazamento completo da configuração de storage S3 (bucket, path, região)
- ALTO: Milhares de imagens listadas com metadados (nomes, datas, tamanhos)
- MÉDIO: Atacante conhece extensões permitidas e estrutura de pastas
- Informação privilegiada sobre estrutura interna do sistema (nomes de arquivos revelam fluxos de trabalho)

## Recomendação
1. Implementar autenticação em TODAS as operações CKFinder (Init, GetFiles, GetFolders)
2. Remover endpoints /ckfinder/connector e /ckfinder/browser de acesso público
3. Configurar ACL apropriada nas resource types do CKFinder
4. Ativar server-side image validation (uploadCheckImages)
5. Se CKFinder não é necessário publicamente, remover rotas do Laravel
