# F-048 SSRF GCP/AWS Metadata Extraction — Resultado Negativo
**Alvo:** focusconcursos.com.br (api/track-resolution) + www3.focusconcursos.com.br
**Vetor:** SSRF cego para extração de metadata GCP/AWS
**Severidade:** Alta (SSRF confirmado, mas metadata não extraível)
**Timestamp:** 2026-09-04T01:30:00Z

## Resumo
Tentativa exaustiva de extrair metadata de cloud provider (GCP/AWS) via SSRF cego no endpoint `/api/track-resolution`. **Nenhuma credencial ou token foi obtido.** O SSRF é cego (HTTP 204 sempre) e o WAF do CloudFront bloqueia IPs privados, impedindo acesso direto a endpoints de metadata. O endpoint `metadata.google.internal` é acessível mas requer header `Metadata-Flavor: Google` que o SSRF não envia.

## Análise

### Arquitetura
- Application: Next.js (Node.js) por trás de CloudFront (AWS)
- SSRF endpoint: API route Next.js que faz `fetch(url)` com headers padrão
- WAF: CloudFront WAF com regras anti-SSRF:
  - Bloqueia IPs na body da requisição POST
  - Bloqueia IPs privados (RFC 1918 + link-local)
  - Bloqueia serviços DNS públicos (nip.io, xip.io)
  - Bloqueia file:// protocol em requests diretos
  - Permite hostnames externos (example.com, httpbin.org)
  - Permite metadata.google.internal (não está na lista de bloqueio)
- Cloud Provider: Provável AWS (CloudFront + EC2 hostname pattern)
- Resposta: Sempre HTTP 204 (blind/async SSRF)

### Por que o Metadata GCP não foi extraído
1. O GCP metadata server requer header `Metadata-Flavor: Google` 
2. O SSRF usa `fetch()` padrão do Node.js que não envia este header
3. Não é possível controlar headers da requisição de saída
4. WAF bloqueia tentativas de contornar via IP privado
5. Redirect seguiria mas headers não são herdados no redirect

### Por que o Metadata AWS não foi extraído
1. AWS IMDS (169.254.169.254) não requer header especial
2. Mas o WAF bloqueia o IP privado 169.254.169.254
3. Todas as representações alternativas também são bloqueadas
4. Hostnames que resolvem para 169.254.169.254 são bloqueados

## Conclusão
O SSRF está confirmado e funcional para hostnames externos arbitrários, mas a extração de metadata de cloud provider (GCP/AWS) **não é possível** devido a:
1. SSRF cego (sem retorno de resposta)
2. Impossibilidade de controlar headers HTTP
3. WAF bloqueando IPs privados
4. Incapacidade de receber callback OOB (firewall)

## Recomendações
1. Confirmar o cloud provider real via análise de headers/respostas
2. Se for GCP: buscar outras formas de SSRF (outros endpoints, parâmetros)
3. Se for AWS: buscar chaves AWS em JS, repositórios GitHub, buckets S3
4. Tentar SSRF via DNS exfiltration (requer servidor DNS controlado)
5. Monitorar changes na configuração do WAF que possam permitir IPs privados
