# F-013 Cred-Stuffing — Nenhuma Credencial Válida Encontrada
Alvo: admin.focusconcursos.com.br/login (Laravel Admin)
Severidade: Info
Timestamp: 2026-08-22T02:15:00Z

## Descrição
Testadas 48 combinações de email × senha contra POST /login do painel admin.
Nenhuma credencial válida encontrada. Login sempre retorna redirect para /login.

## Reprodução

### Endpoints testados
- POST /login (form-urlencoded: _token + email + password)
- Headers: X-CSRF-TOKEN, cookies de sessão

### Combinações (6 emails × 8 senhas = 48 tentativas)
Emails:
1. financeiro@grupofocus.com.br
2. sac@grupofocus.com.br
3. sac@focusconcursos.com.br
4. secretaria@faculdadefocus.com.br
5. luis@focusconcursos.com.br
6. luis@grupofocus.com.br

Senhas:
1. Focus@2024
2. Focus@2025
3. Focus@2026
4. focus123
5. focusconcursos
6. grupofocus
7. Cascavel2024
8. Cascavel2025

### Comportamento
- Todas as tentativas retornam HTTP 302 redirect → http://admin.focusconcursos.com.br/login
- Resposta HTML com `<meta http-equiv="refresh" content="0;url='.../login'" />`
- CSRF token é rotativo a cada requisição (one-time use?)

### Evidência
```
POST /login
_token=RRtzx9FciK995BaAjt...&email=financeiro@grupofocus.com.br&password=Focus@2024
→ 302 redirect para /login (credenciais inválidas)
```

## Interpretação
- Laravel usa autenticação padrão com `Auth::attempt()` ou similar
- CSRF token one-time: cada tentativa consome o token, exigindo novo GET /login
- Sem rate limiting visível (2s de delay foi respeitado, mas não testado sem delay)
- Nenhuma das senhas testadas é válida para qualquer um dos emails

## Impacto
- Nenhum acesso obtido
- As senhas testadas são genéricas/padrão e comuns para ambientes brasileiros
- Possível que as contas tenham senhas fortes ou que estejam desabilitadas

## Recomendação
- Já implementado: CSRF token one-time (boa prática)
- Verificar se rate limiting está configurado (Laravel throttle middleware)
- Auditoria de contas inativas (alguns emails podem ser de ex-funcionários)
