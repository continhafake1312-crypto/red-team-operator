# F-017 CKFinder 3 Browser UI Exposto — /ckfinder/browser
Alvo: admin.focusconcursos.com.br (Laravel Admin)
Severidade: Média
Timestamp: 2026-08-22T02:19:00Z

## Descrição
O endpoint `/ckfinder/browser` retorna a interface HTML do CKFinder 3 File Browser,
permitindo que qualquer pessoa com um navegador acesse o gerenciador de arquivos.

## Reprodução
```
GET /ckfinder/browser HTTP/2
→ HTTP/2 200
Content-Type: text/html; charset=UTF-8

<!DOCTYPE html>
<!-- Copyright (c) 2007-2018, CKSource - Frederico Knabben -->
<html>
<head>
    <title>CKFinder 3 - File Browser</title>
</head>
<body>
    <script src="https://admin.focusconcursos.com.br/js/ckfinder/ckfinder.js"></script>
    <script>CKFinder.config({ connectorPath: "https://admin.focusconcursos.com.br/ckfinder/connector" });</script>
    <script>CKFinder.start();</script>
</body>
</html>
```

## Observações
- CKFinder 3 (build 2018) detectado
- connectorPath aponta para `/ckfinder/connector` (confirmado funcional sem auth)
- CKFinder.start() inicia a UI sem verificação de autenticação
- CKFinder JS não está acessível em `/js/ckfinder/ckfinder.js` (404) — pode estar servido via asset pipeline com hash

## Impacto
- Qualquer pessoa pode abrir o CKFinder em um navegador
- A UI lista todas as pastas e arquivos (via GetFiles/GetFolders)
- Upload e criação de pastas bloqueados (requerem POST autenticado)
- Informação sobre estrutura de diretórios e nomenclatura de arquivos obtida

## Recomendação
- Remover rota /ckfinder/browser de acesso público
- Implementar middleware de autenticação antes de CKFinder.start()
- Se CKFinder for necessário, configurar autenticação no callback CheckAuthentication
