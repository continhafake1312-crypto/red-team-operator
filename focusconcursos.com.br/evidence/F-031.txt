# F-031 JWT Secret Weakness — Secret Found (Crítica)

**Alvo:** focusconcursos.com.br  
**Vetor:** JWT HS256 — Secret Brute Force via Wordlist  
**Severidade:** Crítica  
**Timestamp:** 2026-09-03T17:30:00Z  

## Resumo

O JWT presente no cookie `@focusconcursos:appToken` usa uma chave secreta fraca e previsível para
assinatura HMAC-SHA256. A chave secreta `your-256-bit-secret` foi encontrada via força bruta
utilizando a wordlist `scraped-JWT-secrets.txt` (SecLists), que contém centenas de secrets JWT reais
vazados em aplicações. Esta chave é um valor de placeholder comumente usado em exemplos/documentações
e configurações padrão.

## Evidência Completa

### Token Original
```
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJpbnN0aXR1dGlvbiI6NCwiaWF0IjoxNTE2MjM5MDIyfQ.mn0-q3vdGWFm_XnUpiQr2-WsfMbrKiKMnxaPmyYHe3E
```

### Chave Secreta Encontrada
```
your-256-bit-secret
```

### Verificação
O token original pôde ser decodificado e **verificado** utilizando a chave encontrada. Além disso,
foi possível **recriar exatamente o mesmo token** com a chave e payload originais, confirmando que
a chave é a usada pelo servidor.

### Testes Realizados

1. **Decodificação com a chave encontrada:** ✅ Sucesso
   - `jwt.decode(token, "your-256-bit-secret", algorithms=["HS256"])`
   - Payload decodificado: `{"institution": 4, "iat": 1516239022}`

2. **Re-criação do token original:** ✅ Exato
   - Token recriado: `eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJpbnN0aXR1dGlvbiI6NCwiaWF0IjoxNTE2MjM5MDIyfQ.mn0-q3vdGWFm_XnUpiQr2-WsfMbrKiKMnxaPmyYHe3E`
   - Exatamente igual ao original (mesma assinatura)

3. **Tokens forjados criados:**
   - Institution=1, role=admin
   - Institution=4, role=admin
   - Institution=1..999 com timestamp atual

## Impacto

1. **Forja total de tokens:** Qualquer payload pode ser assinado com a chave conhecida.
2. **Impersonação de instituições:** O campo `institution` no payload pode ser alterado para qualquer valor,
   potencialmente permitindo acesso a dados de outras instituições.
3. **Adição de claims arbitrários:** Claims como `role`, `admin`, `permissions` podem ser adicionados
   se o servidor as validar.
4. **CSRF com CORS:** Combinado com o CORS wildcard (F-003), um atacante pode forjar requisições
   autenticadas de qualquer site.
5. **Validade de 1 ano:** O token não expira, permitindo uso prolongado após descoberta.

## Recomendações

1. **Trocar imediatamente** a chave secreta JWT para uma string aleatória de 256+ bits.
2. **Usar RS256** (assimétrico) ao invés de HS256 (simétrico) para que a chave de verificação seja pública
   e a de assinatura permaneça privada.
3. **Adicionar claims de segurança:** `exp` (expiração curta), `jti` (JWT ID único), `nbf`, `sub` (usuário).
4. **Adicionar HttpOnly, Secure, SameSite=Strict** ao cookie.
5. **Implementar refresh tokens** com validade curta.
6. **Rotacionar secrets** periodicamente.
