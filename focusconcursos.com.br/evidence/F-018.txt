# F-018 Logout Endpoint — Server Error 500 Consistente
Alvo: admin.focusconcursos.com.br (Nginx, Laravel)
Severidade: Média
Timestamp: 2026-08-22T02:38:00Z

## Descrição
O endpoint GET /logout retorna HTTP 500 (Server Error) em TODAS as requisições, independentemente de sessão ativa ou token CSRF. A aplicação falha ao processar a ação de logout sem qualquer validação prévia, indicando um erro não tratado no controller.

## Reprodução

### GET /logout (HTML — sem headers)
```
GET /logout HTTP/2
→ HTTP/2 500
Content-Type: text/html; charset=UTF-8

<!DOCTYPE html>
<html lang="en">
  <head><title>Server Error</title></head>
  <body>
    <div class="code">500</div>
    <div class="message">Server Error</div>
  </body>
</html>
```

### GET /logout (JSON — Accept: application/json)
```
GET /logout HTTP/2
Accept: application/json
→ HTTP/2 500
Content-Type: application/json

{
    "message": "Server Error"
}
```

### GET /logout (AJAX — X-Requested-With: XMLHttpRequest)
```
GET /logout HTTP/2
X-Requested-With: XMLHttpRequest
→ HTTP/2 500
Content-Type: application/json

{
    "message": "Server Error"
}
```

### Métodos HTTP
| Método | Status | Observação |
|--------|--------|------------|
| GET    | 500    | Crash consistente |
| POST   | 405    | Método não suportado |
| PUT    | 405    | Método não suportado |
| DELETE | 405    | Método não suportado |
| PATCH  | 405    | Método não suportado |
| OPTIONS| 200    | Rota existe |

### Com sessão ativa
- Mesmo comportamento: 500 em GET /logout
- Cookies XSRF-TOKEN e admin_session são REGENERADOS a cada request (mesmo no erro 500)
- Não há vazamento de stack trace (APP_DEBUG=false)

## Interpretação
O controller de logout foi definido apenas para GET (POST retorna 405), mas sua implementação lança uma exceção não tratada. Causas possíveis:
- Chamada a Auth::logout() ou auth()->logout() sem guard configurado
- Sessão não inicializada corretamente no middleware
- Banco de dados de sessão indisponível ou migração pendente
- Código personalizado no logout que assume estado que não existe

APP_DEBUG=false impede vazamento de informações, mas o erro 5XX expõe:
- Aplicação instável/Laravel mal configurado
- Um vetor potencial se uma exceção diferente for forçada posteriormente

## Impacto
- MÉDIO: Erro de aplicação exposto publicamente sem necessidade de autenticação
- BAIXO: Negação de serviço funcional parcial (logout quebrado impede troca de sessão)
- BAIXO: O erro pode ser usado como indicador de saúde de aplicação para ataques

## Recomendação
1. Corrigir o controller de logout para tratar o caso sem sessão ativa
2. Validar se a rota deve existir sem autenticação
3. Implementar tratamento de exceções para evitar 500
4. Se logout só deve ser acessível com sessão, adicionar middleware auth
