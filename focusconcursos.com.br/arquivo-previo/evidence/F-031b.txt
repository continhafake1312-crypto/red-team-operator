### ❌ Nenhum acesso privilegiado concedido

Apesar do JWT secret estar correto (confirmado em F-031), os tokens forjados não
concederam acesso administrativo a nenhum subdomínio testado. Possíveis razões:

1. **O servidor não valida claims de role/permissions** — o JWT original só tem
   `institution` e `iat`, e o backend pode ignorar claims extras.
2. **Sessão server-side** — o JWT pode ser apenas um identificador de sessão, com a
   autorização real armazenada no servidor.
3. **Cookie name importa** — alguns hosts usam cookies diferentes do JWT para auth.
4. **CloudFront/WAF bloqueia** — o CDN pode estar interferindo em endpoints que
   exigem sessão real.
5. **CSRF token requerido** — alguns endpoints (Laravel Sanctum) exigem XSRF-TOKEN.

## Recomendações

1. Validar se o secret encontrado pode ser usado para forjar tokens que o servidor aceita
   em outros contextos (WebSocket, API interna, mobile).
2. Testar com sessão real + JWT forjado combinados.
3. Verificar se há rate limiting ou WAF que impede a validação.
4. Investigar se o JWT é usado apenas no frontend Next.js (client-side) e não no backend.
