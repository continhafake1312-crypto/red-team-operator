FINDING F-001: Information Disclosure — Stack Trace Leaks (Tomcat/Spring + com.rlg.ecommerce)
============================================================================================
Hosts: ALL THREE tenants (www.wcursos.com.br PROD, wcursos.sistematutor.com.br TESTE, www.wcursosead.com.br WEAD)
Severity: MEDIUM (unauth tech-stack + internal package/class disclosure on production)
Date: 2026-08-27 (enum phase)

Description:
Tomcat default verbose error pages (with full Java stack traces) are enabled.
Two distinct leak surfaces, reachable UNAUTH:

(A) /multimedia  -> 500 on ALL hosts (incl. PRODUCTION):
    GET https://www.wcursos.com.br/multimedia  -> HTTP 500 (1348 bytes)
    GET https://www.wcursos.com.br/multimedia/ -> HTTP 500 (1624 bytes, different error)
    Exception: java.lang.StringIndexOutOfBoundsException: String index out of range: -1
      java.lang.String.substring(String.java:1931)
      com.rlg.ecommerce.controller.VirtualDirectoryServlet.doGet(VirtualDirectoryServlet.java:79)   <-- E-COMMERCE MODULE
      javax.servlet.http.HttpServlet.service(HttpServlet.java:529)/623
      org.apache.tomcat.websocket.server.WsFilter.doFilter(WsFilter.java:57)
      com.rlg.ecommerce.filter.CheckConnectionFilter.doFilter(CheckConnectionFilter.java:69)       <-- AUTH FILTER
    Footer: Apache Tomcat/9.0.120

(B) WEAD tenant only — /portal/* POST endpoints GETted return 500 with stack traces:
    GET https://www.wcursosead.com.br/portal/enviar-senha       -> 500 (NPE, Spring DispatcherServlet)
    GET https://www.wcursosead.com.br/portal/validar-codigo     -> 500 (NPE)
    GET https://www.wcursosead.com.br/portal/validar-login-juspodium -> 500 (NPE)
    GET https://www.wcursosead.com.br/portal/login             -> 500 (generic error page 298B)
    (PROD/TESTE return clean 200 forms for these — custom error handling differs per tenant)

Disclosed information:
  - Web server:  Apache Tomcat 9.0.120
  - Framework:   Spring MVC (DispatcherServlet/FrameworkServlet) — NOT Struts (corrects prior recon)
  - Servlet API: javax.servlet 5.x
  - E-commerce backend package: com.rlg.ecommerce (RLG vendor)
    - com.rlg.ecommerce.controller.VirtualDirectoryServlet   (mapped at /multimedia/*)
    - com.rlg.ecommerce.filter.CheckConnectionFilter         (auth/connection filter)
  - Student portal backend: Spring MVC controllers (reflection-based invocation)
  - WebSocket support: org.apache.tomcat.websocket.server.WsFilter

Impact:
  - Production leaks stack trace unauth (/multimedia) — confirms exact versions for CVE targeting.
  - Internal class names aid exploit crafting (VirtualDirectoryServlet substring bug = potential
    edge-case input handling issues; CheckConnectionFilter = auth boundary to study).
  - Tomcat 9.0.120 + Spring MVC -> CVE phase should target Tomcat 9.0.x + Spring, NOT Struts.
  - Struts CVEs (S2-045/S2-057) DO NOT APPLY.

Reproduction: curl --proxy socks5://127.0.0.1:9050 -sk https://www.wcursos.com.br/multimedia
Remediation: Disable Tomcat verbose exception pages globally; map 500 to a custom error page.
