# F-300 JWT_SECRET Exposto no GitHub (Credencial Reutilizada)
**Alvo:** arkodex.com.br (produção)
**Severidade:** CRÍTICA
**Timestamp:** 2026-08-26T12:15:00Z
**Status:** Confirmado — secret reutilizado entre projetos

## Descrição
O `JWT_SECRET` do backend foi encontrado hardcoded no repositório GitHub `arkodexx/url-shortener` no arquivo `.env`. Testes confirmaram que o mesmo secret é aceito pela API de produção do arkodex.com.br, indicando reutilização de credenciais entre projetos.

## Evidência
**Repositório:** `arkodexx/url-shortener`
**Arquivo:** `.env` (committed no git)
**JWT_SECRET:**
```
f8431e8ab12c6b485a4c4fe82aad4955cde255b725a4919a68f8329abe49757b7b52463d2c5e64edf92b003c97780d094eccc87e8f5ddc13b3de1b99ebd14424
```

**Histórico do Git** — secret anterior ainda acessível via commit history:
```
SECRET=2e0d34c8eaadb53417fd960599d3286f875da7e76a00c594275734f01028ae63
```
"Removido" no commit `7a85ad2` ("security updates") mas ainda disponível no histórico.

## Teste de Validação
```http
GET /auth/me HTTP/1.1
Host: arkodex.com.br
Authorization: Bearer <JWT assinado com secret>
```
**Resposta:** `{"user":null}` — servidor aceita e valida a assinatura do JWT, mas nenhum userId corresponde a uma sessão real.

Comparação:
- **Sem token:** `{"error":"Não autenticado"}`
- **Token com secret do GitHub:** `{"user":null}` (assinatura válida!)
- **Token inválido (none alg):** `{"error":"Sessão expirada"}`

## Impacto
**CRÍTICO** — Qualquer atacante que encontre este repositório público pode:
1. Forjar JWTs válidos para a API de produção
2. Tentar enumerar userIds até encontrar um ativo
3. Se conseguir um JWT real (via engenharia social ou vazamento), descriptografá-lo e forjar tokens de admin

## Postgres Credenciais Adicionais
Mesmo repositório também expôs:
- **user:** postgres
- **password:** 0302

## Recomendação
1. Rotacionar IMEDIATAMENTE o JWT_SECRET de produção
2. Remover repositórios públicos que contenham credenciais
3. Implementar scanning de secrets no CI/CD (trufflehog/gitleaks)
4. Usar secrets diferentes para cada projeto/ambiente
5. Forçar rotação de senha do PostgreSQL
