# F-008 Wowza Engine Manager + REST API — Cred-brute NEGATIVO (sem cred default/comum)
Alvo: video02.soultv.com.br — Engine Manager (:8088) + REST API (:8087)
Severidade: **Nenhuma** (finding de "tentativa esgotada" — não é uma vuln)
Status: **Confirmado negativo** (96 creds testados, nenhuma válida)
Timestamp: 2026-08-27T16:49:12Z – 16:55:11Z (validado Fase 7b — exploit)

## Sumário
Cred-brute focado contra o login do Wowza Engine Manager
(`/enginemanager/j_spring_security_check`, Spring Security) e observação da REST API
(compartilha `admin.password`). **Nenhuma credencial default/comum funcionou** —
o admin não está em credencial fraca óbvia. Isto bloqueia as chains de RCE que
dependem de cred (CVE-2020-9004 read-only→JMX→RCE, CVE-2024-52052 admin→RCE,
Restlet XXE CVE-2017-14868 que requer cred REST para ler `admin.password`).

## Metodologia
1. GET `/enginemanager/login.htm` (obtém JSESSIONID novo por tentativa — evita
   throttling por sessão; simula fluxo real).
2. POST `/enginemanager/j_spring_security_check` com
   `j_username`, `j_password`, `authType=basicAuth`, `host=localhost`,
   `wowza-page-redirect=`.
3. Critério de sucesso: redirect 302 → `setup.htm`/`Home.htm`/`main.htm`
   (login ok). Falha: redirect 302 → `loginfailed.htm`.
4. 1 tentativa com `authType=digest` (admin/admin) — também falhou.

## Resultado
- **96/96 falhas** (todas → `loginfailed.htm`, 302).
- 1 teste digest admin/admin → falha.
- **Nenhuma cred válida obtida.** `loot/creds.txt` e `loot/access.txt` sem novas
  entradas para video02.
- Não houve indício de lockout/throttle (todas retornaram 302 uniformemente).

## Observações
- O Manager responde 302 → `loginfailed.htm` para cred inválida (não revela se user
  existe vs senha errada — enumerar usuários não é trivial aqui).
- A REST API (:8087) compartilha `admin.password` com o Manager → cred válida
  funcionaria em ambos; não houve razão para brute separado.

## Impacto / próximo passo
- **Nenhuma vuln confirmada por este teste.** Resultado negativo documentado para
  evidenciar que o caminho "cred default → RCE" foi exaustivamente tentado.
- Próximos vetores para cred (não executados nesta fase, falta contexto/autorização
  para ataque mais agressivo):
  1. Brute maior (rockyou top-N) — alto risco de lockout/IDS; requer decisão do
     coordenador.
  2. Obter `admin.password` via outra via: SSRF interno, leak de backup, FTP
     (anônimo está vazio), SVN/.git exposto, ou cred vazada em breach externa
     (OSINT — delegar a `osint`).
  3. CVE-2024-52053 UNAUTH XSS chain (requer admin ativo visualizando Manager —
     dependência UI:R, não-garantido em IPTV produção).
  4. Expor/explorar `18.231.132.245` (worker interno, "Secret Hunter v2"
     dashboard) que pode vazar creds do próprio Wowza.
