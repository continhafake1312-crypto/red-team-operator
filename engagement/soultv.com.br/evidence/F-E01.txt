# Evidence F-E01 — JMX RMI default credentials on video02 (160.202.130.243)

> Specialist: `enum` | Phase 5 | Date: 2026-08-27 | CVSS est: 9.1 (CRITICAL)

## Target
- Host: `video02.soultv.com.br` (160.202.130.243) — origin real, **bypass Cloudflare**
- Ports: 8084/tcp (java-rmi, JMX RMI connection port), 8085/tcp (java-rmi, JMX RMI registry port)
- Service: Wowza Streaming Engine 4.8.0 JMX RMI interface (default rmiConnectionPort=8084, rmiRegistryPort=8085)

## Vulnerability
Wowza JMX RMI listener (port 8084/8085) accepts the **default credential `admin:admin`** (jmxremote.password left at default). The JMX registry on 8085 exposes the bound name `/jmxrmi` (RMIServerImpl_Stub) to **unauthenticated lookup**; the stub endpoint advertises `localhost:8084` (rmiServerHostName=localhost default) — a custom RMISocketFactory redirecting localhost→160.202.130.243 was used to complete the connection.

## Chain to full RCE root (for `exploit`)
Two paths:
- **(A) CVE-2020-9004 chain:** obtain ANY valid Manager credential (read-only or admin) at 8088 → POST `/enginemanager/server/serversetup/edit_adv.htm` (params: `rmiServerHostName=0.0.0.0`, `authenticate=false`) → POST `/enginemanager/server/restart.htm` → reconnect JMX **unauthenticated** (now readwrite, access file bypassed) → MLet `createMBean` from remote URL → RCE root.
- **(B) jvmtiAgentLoad:** place a malicious JVMTI agent `.so`/`.jar` on the server filesystem (via any writable service — FTP anon is read-only; candidate: Wowza HTTP provider upload, REST API with creds) → `jvmtiAgentLoad` → RCE root.

Blockers observed: Manager 8088 admin:admin = loginfailed; REST 8087 admin:admin + common creds = 401; FTP anon read-only (MKD/STOR denied). `admin.password` (REST/Manager) is NOT the JMX `jmxremote.password`.
