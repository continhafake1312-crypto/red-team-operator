## Nota: Manager e REST compartilham `conf/admin.password`
Os dois painéis leem credenciais do mesmo arquivo `conf/admin.password` (Wowza). Logo o
conjunto de creds válidas é idêntico. O brute do Manager (96) já cobriu o universo plausível;
o brute do REST confirma a inexistência de cred fraca/default. A cred real do `admin.password`
não é default nem óbvia — exige:
- leitura do arquivo `conf/admin.password` (CVE-2021-31539 — plaintext em 4.8.0, mas requer
  file-read primitive: XXE Restlet CVE-2017-14868 com cred REST — circular; ou path traversal
  em REST — fix em 4.7.5, não aplica a 4.8.0), ou
- filesystem access via pivoting interno, ou
- brute de dicionário maior (não-destrutivo apenas dentro do threshold autorizado).

## Impacto
- A exposição dos painéis admin (Manager + REST) diretamente na origem (bypass Cloudflare)
  é por si só um risco Alto — qualquer cred vazada/fracassada leva a admin do streaming.
- A ausência de rate-limiting / lockout observada durante o brute (todos os 96+40 requests
  processados sem bloqueio) indica que um dicionário maior seria viável (não executado —
  limite de threshold e OPSEC).
- Bloqueia a chain de RCE root CVE-2020-9004 (precisa de cred read-only no Manager).

## Recomendação
1. **Firewall:** restringir 8088/8087 a IPs administrativos (VPN/bastion); nunca expor à
   internet. Bypass de Cloudflare já expõe a origem.
2. **Cred forte** em `admin.password` (não default, não dicionário).
3. **Rate-limit / lockout** no login do Manager (Spring Security: contar tentativas por IP).
4. **Atualizar Wowza ≥4.9.1** (corrige CVEs que poderiam ler `admin.password`).
