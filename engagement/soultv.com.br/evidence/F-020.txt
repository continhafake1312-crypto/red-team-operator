# F-020 — JMX/RMI Porta 8084 Exposta (Probe Inconclusivo)

## Metadados
- **Alvo:** video02.soultv.com.br (160.202.130.243:8084)
- **Severidade:** Média (potencial Crítica se JMX unauth)
- **Status:** Inconclusivo (RMI responde, mas registry sem bindings)
- **Data:** 2026-08-27T20:05Z

## Descrição
A porta 8084 do servidor Wowza Streaming Engine 4.8.0 responde ao protocolo JRMI
(Java Remote Method Invocation), confirmando que um serviço RMI/JMX está exposto.
No entanto, o RMI registry não contém bindings acessíveis (`NoSuchObjectException:
no such object in table` ao tentar `registry.list()`).

## Evidência

### RMI Protocol Handshake (via Tor)
```
Python socket via SOCKS5 (127.0.0.1:9050):
→ Send: JRMI\x00\x02\x4b (JRMP protocol, version 2, StreamProtocol)
← Recv: 4e000e3137382e31372e3137312e3130320000ba9c
  N = JRMP ack
  hostname = 178.17.171.102 (Tor exit node — confirma OPSEC)
  port = 47772
```

### RMI Registry List (via Java + SOCKS proxy)
```java
Registry reg = LocateRegistry.getRegistry("160.202.130.243", 8084);
reg.list() → java.rmi.NoSuchObjectException: no such object in table
```

### jmxterm Connection
```
java -DsocksProxyHost=127.0.0.1 -jar jmxterm.jar --url service:jmx:rmi:///jndi/rmi://160.202.130.243:8084/jmxrmi
→ Failed to retrieve RMIServer stub: NoSuchObjectException: no such object in table
```

## Interpretação
1. A porta 8084 está ABERTA e responde ao protocolo RMI/JRMP
2. O RMI registry NÃO tem bindings acessíveis — o serviço pode:
   - Requerer autenticação (JMX com password)
   - Usar um path JNDI diferente (não `jmxrmi`)
   - Ser um servidor RMI direto (não um registry)
3. Nmap classificou como "websnp?" (serviço desconhecido)

## Impacto
Se JMX estiver acessível sem auth → CVE-2020-9004 (RCE root). Mas o registry
não está acessível via método padrão. Requer ferramentas especializadas
(metasploit auxiliary/scanner/misc/jmx_server, ou manual RMI exploitation).

## OPSEC
- Primeiro probe foi feito com Python socket DIRETO (sem Tor) — expôs IP real
  18.231.132.245 ao alvo. Segundo probe via Tor confirmou (IP exit 178.17.171.102).
- **Incidente OPSEC registrado em timeline.log.**

## Recomendação
Fechar porta 8084 para IPs não confiáveis. Se JMX necessário, usar autenticação
(JMX password file) e TLS.
