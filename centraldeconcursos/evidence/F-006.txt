FINDING F-006 — Backend Render direto bypassa Cloudflare WAF + tenant resolvido por header Origin
==============================================================================

## Alvo / Host
- Backend PROD direto (bypass CF): https://seducar-api-website.onrender.com
- Backend HML direto (bypass CF):  https://seducar-api-website-hml.onrender.com
- Backend PROD via CF (WAF ativo):  https://api.centraldeconcursos.com.br
- Stack: AdonisJS (Node.js) on Render (cookie `adonis-session`), multi-tenant Seducar

## Severidade: ALTA
Bypass de controle de segurança (WAF Cloudflare) expondo a superficie completa
da API multi-tenant Seducar (24 endpoints `/api/v1/*`) diretamente no backend
de origem (Render), incluindo rotas financeiras e de PII. O WAF que protege
`api.centraldeconcursos.com.br` (que retorna 404 para `/api/v1/*`) é totalmente
contornado acessando o hostname do Render diretamente. Resolução de tenant via
header `Origin` permite direcionar requisições a qualquer escola Seducar
configurada (centraldeconcursos, degraucultural, homolog).

## Timestamp
2026-08-27T16:50Z UTC (descoberta) — 2026-08-27T16:55Z (confirmado)

## Reprodução
```
# 1. CF-fronted: WAF bloqueia /api/v1/* (retorna 404 — não chega ao backend)
$ curl --socks5-hostname 127.0.0.1:9050 -s https://api.centraldeconcursos.com.br/api/v1/auth/me
{"..."}  # HTTP 404, 59 bytes (CF responde 404, rota bloqueada pelo WAF)

# 2. Backend Render direto, SEM Origin: tenant não resolvido
$ curl --socks5-hostname 127.0.0.1:9050 -s https://seducar-api-website.onrender.com/api/v1/auth/me
{"error":"Escola não encontrada"}

# 3. Backend Render direto, COM Origin do tenant central: tenant RESOLVIDO
$ curl --socks5-hostname 127.0.0.1:9050 -s \
    -H "Origin: https://centraldeconcursos.com.br" \
    https://seducar-api-website.onrender.com/api/v1/auth/me
{"error":"Token não fornecido."}      # <-- tenant resolvido, próximo gate = auth

# 4. Cross-tenant: Origin do concorrente também resolve
$ curl -H "Origin: https://degraucultural.com.br" https://seducar-api-website.onrender.com/api/v1/auth/me
{"error":"Token não fornecido."}      # <-- tenant degrau resolvido no mesmo backend

# 5. Origin arbitrário (não-cadastrado): rejeitado (allowlist de escolas)
$ curl -H "Origin: https://evil.example.com" https://seducar-api-website.onrender.com/api/v1/auth/me
{"error":"Escola não encontrada"}     # <-- allowlist valida escolas conhecidas
```

## Output (mapeamento de superficie exposta — backend Render direto)
Endpoints que EXISTEM (retornam 401 "Token não fornecido." com Origin válido) e
são bloqueados/404 no CF-fronted `api.centraldeconcursos.com.br`:

  /api/v1/auth/me                      (identidade)
  /api/v1/classroom/dashboard
  /api/v1/classroom/orders             (FINANCEIRO — pedidos)
  /api/v1/classroom/orders/
  /api/v1/classroom/contracts          (FINANCEIRO — contratos)
  /api/v1/customers/products/{id}      (IDOR — produtos do cliente)
  /api/v1/customers/lessons/notes/{id} (PII — notas de aulas)
  /api/v1/support/tickets              (PII — tickets suporte)
  /api/v1/support/tickets/{id}         (IDOR — ticket específico)
  /api/v1/auth/login  (POST)           (login — enumerável, ver F-007)
  /api/v1/auth/register (POST)         (registro — requer nome/CPF/senha)
  /api/v1/public/contests              (200 — dados públicos legítimos)

Endpoints que NÃO existem como GET (retornam `<p> Cannot GET:... </p>`):
  /api/v1/classroom/orders/{id}, contracts/{id}, contests/{id}, lessons/{id},

Mapeamento de rotas feito via AdonisJS router. Backend revela `set-cookie:
adonis-session` (cookie de sessão AdonisJS assinado) mesmo em respostas 401.

Headers notáveis do backend Render direto:
  server: cloudflare                 (Render na frente de CF edge, mas sem WAF rules)
  x-render-origin-server: Render
  x-ratelimit-limit: 5               (rate-limit no endpoint de login)
  x-ratelimit-remaining: N
  access-control-allow-credentials: true   (ver F-008 — CORS cross-tenant)
  access-control-allow-origin: <refletido do Origin>

## Interpretação
1. **Bypass de WAF:** `api.centraldeconcursos.com.br` é protegido por Cloudflare
   com regras WAF que bloqueiam `/api/v1/*` (retornam 404 para o público). No
   entanto, o backend real roda em `seducar-api-website.onrender.com` (Render),
   que é publicamente acessível diretamente (CSP do apex o lista como `apiUrl`).
   Qualquer atacante pode bater direto no hostname do Render, contornando
   completamente as regras WAF/roteamento do CF. Isso expõe a superficie completa
   de endpoints `/api/v1/*` da plataforma Seducar.
2. **Resolução de tenant por Origin:** O backend é multi-tenant e resolve a
   "Escola" (tenant) pelo header `Origin` (não por Host/subdomínio, como o recon
   ativo havia presumido — o CF bloqueia Host spoofing, mas o backend Render
   direto aceita Origin arbitrário para resolução de tenant). Origens
   reconhecidas (centraldeconcursos.com.br, degraucultural.com.br,
   homolog.centraldeconcursos.com.br) resolvem para seus tenants; origens
   desconhecidas são rejeitadas ("Escola não encontrada").
3. **Superficie financeira/PII exposta:** Com um Origin válido, todos os
   endpoints protegidos retornam "Token não fornecido." (existe, requer auth)
   em vez de 404. Isso confirma que as rotas de orders/contracts/tickets/
   customers existem e estão prontas para receber tokens — alvos de IDOR/BOLA
   assim que um token válido for obtido (via cred-stuffing ou conta de teste).
4. **Backend HML mais permissivo:** `seducar-api-website-hml.onrender.com`
   resolve tenant DEFAULT sem Origin (todos endpoints retornam "Token não
   fornecido." mesmo sem header Origin) — HML tem tenant default configurado,
   superficie mais exposta + debug mode ligado (ver F-009).

## Impacto
- Bypass do único controle de perímetro (WAF Cloudflare) que protege a API.
- Exposição da arquitetura multi-tenant Seducar (24 endpoints, framework
  AdonisJS, rate-limit de 5 no login, cookie de sessão).
- Vetor habilitador para: (a) enumeração de emails (F-007), (b) cred-stuffing
  no login (`/api/v1/auth/login`), (c) IDOR/BOLA cross-tenant nos endpoints
  financeiros/PII assim que token obtido, (d) abuso do registro público
  (`/api/v1/auth/register`) para criar conta low-priv e testar IDOR interno.
- Confirmação que degraucultural.com.br (concorrente / outro cliente Seducar)
  é um tenant válido no MESMO backend — risco de confusão cross-tenant se
  isolamento por token/Origin for imperfeito.

## Recomendação
1. Restringir o backend Render para aceitar tráfego SOMENTE via Cloudflare
   (IP allowlist dos ranges CF no firewall do Render, ou Authenticated Origin
   Pulls / mTLS entre CF e origin). Atualmente o hostname
   `seducar-api-website.onrender.com` é público e bypassa todo o WAF.
2. Não confiar em header `Origin` para resolução de tenant — validar tenant
   exclusivamente pelo token JWT (claim de tenant/school) assinado pelo
   servidor de auth. Header Origin é controlável pelo cliente.
3. Mover o hostname do Render para um nome não-publicamente-descobrível não
   resolve (security by obscurity) — usar restrição de origem real (item 1).
4. Garantir que o isolamento de tenant nos endpoints autenticados seja por
   claim do JWT (school_id do token), NÃO por Origin/Host, para evitar IDOR
   cross-tenant (validar com teste de token de tenant A + Origin de tenant B).
