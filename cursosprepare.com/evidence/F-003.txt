# FINDING F-003 — 30 páginas de cursos pagos acessíveis sem autenticação (challenge-page IDOR)

## Severidade: ALTA

## Resumo
Todos os 30 `challenge-page/<UUID>` (Wix Online Programs — cursos pagos) retornam HTTP 200 com conteúdo completo (1.1-1.2MB cada) sem requerer autenticação. UUIDs foram enumerados via sitemap público (`sm_online-programs.xml`). O conteúdo inclui páginas de curso com referências a gating de membro ("locked", "premium", "paid", "Login") no HTML, mas a página carrega sem redirecionamento para login.

## Endpoint (exemplo)
```
GET https://www.cursosprepare.com/challenge-page/1031f84a-d99d-47a7-b059-1c36914161ec
→ HTTP 200, 1157328 bytes
Title: "Matemática - Fundatec | Cursos Prepare"
```

## Cursos expostos (30)
Inclui cursos preparatórios para concursos de prefeituras (Agudo, Tapera, Toropi, Silveira Martins, Ijuí, Novo Hamburgo, Santo Ângelo, Cachoeira do Sul, Redentora, Relvado), Brigada Militar RS, cursos Fundatec/Legalle (Matemática, Português, Raciocínio Lógico, Fundamentos da Educação, Informática, Legislação).

Lista completa em `enum/www.cursosprepare.com/challenge_pages_status.txt` (30 UUIDs + sizes) e `challenges_list.tsv` (UUID + título).

## Comportamento de acesso
- Todas as 30 páginas retornam 200 sem auth (via bypass apex IP).
- HTML contém: 632 referências a "member", 74 a "Login", 25 a "locked", 11 a "premium", 3 a "paid".
- Indica que há gating no nível da aplicação (Wix Members), mas a página HTML é servida — possível que o conteúdo do curso seja exibido ou que o gating ocorra via JS client-side (bypassable).

## Impacto
- Acesso não-autorizado a material de cursos pagos (se o conteúdo for exposto no HTML inicial).
- Bypass de paywall se o gating for client-side.
- Enumeração de cursos via sitemap facilita mapeamento do catálogo.

## Pendente (validar na fase webapp)
- Determinar se o conteúdo do curso (vídeos/material) é exposto no HTML inicial ou carregado via API autenticada.
- Se client-side gating, demonstrar bypass (extrair conteúdo pago).
- Testar acesso a conteúdo via APIs Wix Online Programs usando tokens vazados (F-002).

## Evidência
- `enum/www.cursosprepare.com/challenge_pages_status.txt` — 30 UUIDs com status 200 e tamanhos
- `enum/www.cursosprepare.com/challenge_page_sample.html` — sample HTML (1.1MB)
- `enum/www.cursosprepare.com/challenges_list.tsv` — UUID + título
- `enum/www.cursosprepare.com/challenge_uuids_api.txt`
- Sitemap: `recon/passive/sm_online-programs.xml`

## CVSS
AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N → 7.5 (Alta) — pendente confirmação de exposure de conteúdo pago.

## Recomendação
- Implementar gating server-side para conteúdo de cursos pagos (não confiar em JS client-side).
- Requerer autenticação antes de servir HTML de challenge-page.
- Remover UUIDs de cursos do sitemap público ou requerer auth para o sitemap.

## Validação Fase 6 (webapp) — 2026-08-27T16:40Z
- **F-003 REFUTADO como "paywall bypass" de conteúdo pago**. Investigação aprofundada:
  - `challenge-page/<UUID>` (1.1-1.2MB) expõe APENAS a **landing page pública de marketing** do curso: título, duração, nº de etapas, descrição/ementa completa, preço (ex: "Matemática - Fundatec", 120 dias, 5 etapas, R$ 40,00) — **conteúdo de marketing intencionalmente público** (accessType=PUBLIC confirmado via F-004).
  - O HTML **NÃO contém** o conteúdo das aulas (vídeos, PDFs, texto das etapas): não há `videoUrl`, `mediaUrl`, `.mp4`, `.pdf` no HTML nem no blob JSON do viewerModel. Não há `__INITIAL_STATE__`/`__APOLLO_STATE__` com steps.
  - O conteúdo das etapas é carregado via `/_api/challenge-service-web/api/v1/...` APÓS enrollment: `POST /challenges/{id}/steps` retorna **400 "actionId is not a valid GUID"** (requer `actionId` de enrollment — não reproduzível anonimamente).
  - `/participant-page/<UUID>` (visão do aluno inscrito) retorna 200 mas exibe **"Você não tem acesso a essa página. Contate o proprietário do site"** — gating server-side correto; não bypassa.
  - `/participant-page?challengeId=...` idem (gated, mostra Login).
  - API `participants/{challengeUUID}` → **403 PERMISSION_DENIED**.
- **Reclassificação**: F-003 deve ser **DOWNGRADED de ALTA para BAIXA/INFO**. O "acesso sem auth às 30 challenge-pages" é o comportamento pretendido (landing pages públicas de cursos PUBLIC). O paywall está corretamente enforced server-side: o conteúdo das aulas (vídeos/PDFs/steps) NÃO é exposto a visitantes. Único residual: UUIDs de cursos enumeráveis via sitemap público (baixo risco).
- A métrica real (participantes/inscritos por curso) está em F-004, que é o achado relevante da superfície de Online Programs.
- Artefatos webapp: `webapp/challenge_page_sample.html` (enum), `webapp/steps_post.json` (400 actionId), `webapp/page_participant-page.html` ("não tem acesso"), análise de `webapp/json_blob_0_809588.json`.
- **Conclusão**: F-003 NÃO confirma bypass de paywall. Conteúdo pago está protegido. Recomenda-se apenas restringir UUIDs no sitemap público (info).
