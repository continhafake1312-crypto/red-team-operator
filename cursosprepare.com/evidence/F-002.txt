# FINDING F-002 — Tokens Wix vazados sem autenticação (dynamicmodel + access-tokens)

## Severidade: ALTA

## Resumo
Os endpoints `/_api/v2/dynamicmodel` e `/_api/v1/access-tokens` retornam 200 sem autenticação, vazando tokens sensíveis da plataforma Wix: `metaSiteId`, `visitorId`, `svSession`, `mediaAuthToken` (JWT), `ctToken`, e tokens de instância de todos os TPA apps instalados.

## Endpoints
```
GET https://www.cursosprepare.com/_api/v2/dynamicmodel     → 200 (86KB)
GET https://www.cursosprepare.com/_api/v1/access-tokens      → 200 (86KB)
```
(rota via apex IP `--resolve www.cursosprepare.com:443:185.230.63.171`)

### mediaAuthToken JWT payload
```json
{"iss":"app:1126553514120352","sub":"site:dcffb6fe-b153-4b2e-bd44-5de8281fcb28","aud":"urn:service:file.upload","exp":1787893996,"iat":1787807596,"jti":"yPKbWZzCGjUVv4Pn1dma_g","addedBy":"anonymous:f4a1a770-1c6a-4765-abcd-46f7f413f556"}
```
- `aud: urn:service:file.upload` — token autoriza **upload de arquivos** ao site.
- `exp: 1787893996` — expira em ~24h.

### TPA app instance tokens (17 apps)
Inclui: Wix Subscriptions/Notifications, Wix Bookings Services, e 15 system apps. Cada um com `instanceId` e `demoMode=False` (modo produção).

## Impacto
- `mediaAuthToken` (aud `file.upload`) — permite tentar upload não-autorizado de arquivos ao site (potencial RCE/storage abuse dependendo das permissões Wix).
- `svSession` — session token de visitor; pode ser usado para interagir com APIs Wix como visitor autenticado.
- `metaSiteId` + app instance IDs — informação para escalar ataques contra APIs Wix (Stores, Bookings, Members, Online Programs).
- `ctToken` — contém User-Agent do request (menor risco).

## CVSS
AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:L/A:N → 7.4 (Alta)

## Recomendação
- Requerer autenticação para `/_api/v2/dynamicmodel` e `/_api/v1/access-tokens`, ou remover tokens sensíveis (mediaAuthToken, svSession) de respostas a visitantes anônimos.
- Validar que mediaAuthToken com `aud:file.upload` não permita upload de arquivos perigosos.

---

## Validação Fase 6 (webapp) — 2026-08-27T16:25Z
- **Reproduzido**: tokens re-obtidos em runtime (`webapp/tokens_fresh.json`, 86KB) — mesmos campos: metaSiteId, visitorId, svSession (288 hex), mediaAuthToken (JWT HS256, aud `urn:service:file.upload`, exp ~24h), ctToken, hs, e 17+ app instance tokens.
- **mediaAuthToken upload abuse — testado e NÃO viável a partir deste path**:
  - `files.wix.com` retorna **403 (Google App Engine firewall)** em `/v1/upload/files`, `/v1/upload/url`, `/upload` via Tor exit — bloqueio em camada de rede (não auth).
  - Via multipart e JSON init, todos os endpoints de upload do Wix Media retornaram 403/404.
  - Mesmo se o upload funcionasse, o design da Wix isola uploads de visitantes em pasta temporária sandbox (não a media gallery do site) — risco de RCE/storage abuse limitado.
  - **Conclusão**: mediaAuthToken vazado é info disclosure + risco teórico, mas o upload abuse não foi confirmado explorável.
- **Consequência crítica do vazamento (confirmada)**: os `instance` tokens dos apps Wix (Members, Online Programs) vazados aqui habilitam diretamente F-001 (members leak) e F-004 (catálogo + métricas). O `instance` token é a chave de acesso — sem auth de usuário — às APIs dos TPA apps.
- Artefatos webapp: `webapp/tokens_fresh.json`, `webapp/access_tokens_fresh.json`, `webapp/up_init1.json`, `webapp/up_url.json` (403 GAE).
- Severidade mantida ALTA (token leak habilita F-001/F-004; mediaAuthToken upload teórico).
