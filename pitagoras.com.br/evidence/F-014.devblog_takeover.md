# F-014 dev.blog.pitagoras.com.br — AWS ELB Subdomain Takeover

Alvo: dev.blog.pitagoras.com.br  
Severidade: Alta  
Timestamp: 2026-08-20T08:00:00Z  
Tipo: DNS Subdomain Takeover (CNAME dangling)

## Resumo

O subdomínio `dev.blog.pitagoras.com.br` possui um registro CNAME apontando para  
`cogna-blogs-228897537.us-east-1.elb.amazonaws.com`, que atualmente retorna NXDOMAIN  
(ELB não existe mais). Isso configura um subdomain takeover clássico.

## Evidência

### DNS Records
```
CNAME: dev.blog.pitagoras.com.br → cogna-blogs-228897537.us-east-1.elb.amazonaws.com
Target: ELB retorna NXDOMAIN (não existe)
```

### Verificação
```bash
dig @8.8.8.8 dev.blog.pitagoras.com.br CNAME +short
→ cogna-blogs-228897537.us-east-1.elb.amazonaws.com.

dig @8.8.8.8 cogna-blogs-228897537.us-east-1.elb.amazonaws.com ANY +short
→ (vazio — NXDOMAIN)

host dev.blog.pitagoras.com.br 8.8.8.8
→ NXDOMAIN (serviço inexistente)
```

### Nameservers
```
pitagoras.com.br NS: Azure DNS (ns1-06.azure-dns.com, ns2-06.azure-dns.net)
```

## Impacto
- Qualquer atacante que consiga registrar um ELB com nome similar pode assumir o subdomínio
- AWS ELB DNS name: `{name}-{hash}.{region}.elb.amazonaws.com`
- O hash `228897537` é específico da conta AWS original
- Potencial para phishing, roubo de sessão, malware

## Limitação
- O hash do ELB é account-specific, impossível de recriar exatamente
- Porém: se a conta AWS for identificada, outros serviços podem ser alvo
- Recomendar remoção imediata do CNAME ou apontar para um endpoint válido

## Recomendação
1. Remover registro CNAME para ELB inexistente
2. Ou criar um novo ELB/ALB e atualizar o DNS
3. Verificar outros subdomínios para dangling DNS
