=== ENDPOINTS EXTRAÍDOS DE app.min.js (live + wayback) ===

## Auth endpoints (apex)
- POST /api/auth/login  {username, password}         (rate 5/window, Turnstile no apex; SEM Turnstile no api)
- GET  /api/auth/verify                            → retorna user.tipo (admin/client), user.plano, user.diasRestantes
- POST /api/auth/pre-register                       (rate 3/window; retorna token -> localStorage "qb_pagamento_context" {preRegisterToken})
- POST /api/auth/logout
- POST /api/auth/complete-reset                    (Turnstile)

## Consultas PII (apex) — fetch hook adiciona X-QB-Nonce + X-QB-Sig
- POST /api/consultas/nonce                        (rate 10/IP) → {nonce, sig}
- POST /api/consultas/verificar-humano  {token}    (Turnstile verify; response pode ter requireCaptcha, siteKey, action)
- GET  /api/user/modulos                           → {success, modulos:[{rota, limiteUsado, limiteTotal, unlimited, enabled}]}
- Padrão interceptado: /api/(consultas|geradores)/<rota> e /geradores/<rota>
- /api/telegram/data/<md5>                          (interceptado pelo hook p/ capturar __qbResult)

## Pagamento (apex)
- POST /api/gerar-pix                              (rate 30 GLOBAL)
- POST /api/pagamento/verificar  {token}

## Headers custom de consulta
- X-QB-Nonce: <nonce>
- X-QB-Sig:   <sig>
(lógica: 403 + {requireCaptcha:true} → dispara Turnstile → POST verificar-humano → refaz req)

## statusMessage codes observados (p/ enum de estados)
- "NoPlan"          → 403 (sem plano)
- "PlanExpired"     → 403 (plano expirado)
- (outros: limite diário atingido, etc.)
