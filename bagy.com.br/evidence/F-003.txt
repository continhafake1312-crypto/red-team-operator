## Interpretação

A configuração do Firebase está exposta publicamente via Firebase Hosting no subdomínio
ig.bagy.com.br. Embora o database tenha sido desabilitado e o storage esteja protegido,
a exposição da API Key permite:

1. Utilizar a API Key para autenticação anônima no Firebase Auth (signUp/signIn)
2. Potencial enumeração de usuários via Firebase Auth REST API
3. Se o storage for acessível via outra configuração de permissão, upload/download de arquivos
4. Acesso à Firebase Cloud Messaging (enviar notificações)

Embora uma Firebase API Key por si só não seja considerada crítica (Google recomenda
que chaves de API para Firebase sejam públicas), a exposição combinada com a possibilidade
de autenticação anônima abre superfície para ataques como abuso de quota, enumeração de
contas, ou exploração de serviços Firebase mal configurados.

## Impacto

- Enumeração de contas de usuário via Firebase Auth (se signIn com email e senha estiver habilitado)
- Abuso de quota dos serviços Firebase (Auth requests, Storage bandwidth)
- Potencial acesso a dados se alguma regra de segurança estiver mal configurada
- Phishing direcionado usando o Firebase Hosting do projeto

## Recomendação

1. Revisar a necessidade de expor a configuração do Firebase no client-side do ig.bagy.com.br
2. Implementar App Check no Firebase para restringir chamadas de API a origens autorizadas
3. Revisar as regras de segurança do Firebase (Auth, Firestore, Storage, Functions)
4. Se o projeto não for mais utilizado, deletá-lo completamente do console Firebase
5. Garantir que o Realtime Database e Storage tenham regras restritivas (só usuários autenticados)
