# F-030 — Inventário Completo de /wp-content/uploads/ (Enumeração de PII)

**Alvo:** `https://matriculas.fernandapessoa.com.br` + `https://acaorelampago.fernandapessoa.com.br` (IP real 187.45.185.33)
**Severidade:** Baixa (misconfiguration — directory listing — sem PII exposta)
**Timestamp:** 2026-08-28T01:30–01:55 UTC
**Classificação:** Information Disclosure / Directory Listing (CWE-548) — conteúdo não-sensível
**Findings relacionados:** F-030 (dir listing original)

## Objetivo

Caçar PII de alunos (certificados, comprovantes, documentos pessoais, planilhas
de matrícula) em `/wp-content/uploads/` dos 4 hosts WordPress, dado que o
directory listing está habilitado (F-030).

| acaorelampago.fernandapessoa.com.br | 200 — Apache Index of | Sim (WP 5.3.18) |
| loja.fernandapessoa.com.br | 404 (cPanel error page) | NÃO (não-WP) |

→ Apenas `matriculas` e `acaorelampago` possuem `/wp-content/uploads/` (são o
MESMO WP install — vhosts apontando para o mesmo docroot; conteúdo idêntico).

## Interpretação

Apesar do nome `matriculas.fernandapessoa.com.br` (subdomínio de matrículas), o
`/wp-content/uploads/` **NÃO contém nenhum documento de matrícula, certificado,
comprovante ou planilha de alunos**. O conteúdo é exclusivamente a mídia de
demonstração do WordPress instalado em 2020/04 (post "Olá Mundo" + logos do tema
CFP). Todos os diretórios de mês subsequentes existem (porque o WP os cria
automaticamente ao agendar/publicar posts) mas estão vazios — o site nunca
recebeu uploads de mídia reais após a instalação inicial.

O `loja.fernandapessoa.com.br` não é WordPress (página de erro cPanel — provável
instalação de e-commerce diferente em outro docroot) e `fernandapessoa.com.br`
também não tem `/wp-content/` (HTTP 404 Apache).

## Impacto

- **PII exposta: NÃO.** Nenhum documento pessoal, certificado, comprovante ou
  planilha de aluno está acessível via directory listing.
- O directory listing (F-030) permanece como misconfiguration de Baixa severidade:
  expõe apenas a estrutura de diretórios e a mídia demo do WP (imagens genéricas,
  logos do tema). Nenhum dado sensível vazado.
- Impacto real limitado: enumeração da árvore de uploads + nomes de arquivos de
  mídia (pode vazar nomes de usuários se uploads futuros usarem padrão
  `<usuario>-<arquivo>`, mas nada disso ocorreu até 2026/08).

## Recomendação

1. **Desabilitar directory listing** globalmente no Apache:
   `Options -Indexes` em `<Directory>` do docroot (ou no .htaccess do wp-content).
2. **Bloquear listagem** de `/wp-content/uploads/` via nginx (o front é nginx):
   ```nginx
   location ~* ^/wp-content/uploads/ { autoindex off; }
   location ~* ^/wp-content/uploads/$ { return 403; }
   ```
3. Proteger `/wp-content/uploads/` com regra que bloqueie acessos a raiz de
   diretório (permitir apenas arquivos específicos).
4. Revisar se o subdomínio `matriculas` deveria armazenar documentos sensíveis
   em outro backend (atualmente o WP é apenas demo — não há fluxo de upload de
   documentos de matrícula implementado neste WP).
