# F-033 — JWT "none" Algorithm Attack

## Finding
The `api-beta.stormapplications.com` backend properly rejects JWT tokens with `alg: none` (no signature). All variants of the "none" algorithm attack were tested and none succeeded.

## Tested Variations

| Variant | Signature | Typ (payload) | Result |
|---------|-----------|---------------|--------|
| `alg: none` | empty string | admin | 404 NOT_FOUND |
| `alg: none` | `.` | admin | 404 NOT_FOUND |
| `alg: none` | `x` (placeholder) | admin | 404 NOT_FOUND |
| `alg: None` | empty string | admin | 404 NOT_FOUND |
| `alg: NONE` | empty string | admin | 404 NOT_FOUND |
| `alg: null` | empty string | admin | 404 NOT_FOUND |
| `alg: none` | empty string | user | 404 NOT_FOUND |
| `alg: none` | empty string | auth | 404 NOT_FOUND |
| `alg: none` | `.` | user | 404 NOT_FOUND |
| `alg: none` | ` ` (space) | admin | 404 NOT_FOUND |
| `alg: none` | `none` (word) | admin | 404 NOT_FOUND |
| `alg: none` + `kid: none` | `.` | admin | 404 NOT_FOUND |
| `alg: none` + `crit: ["exp"]` | `.` | admin | 404 NOT_FOUND |
| `alg: none` (no trailing dot) | (empty) | admin | 404 NOT_FOUND |
| `alg: none` (double trailing dot) | `..` | admin | 404 NOT_FOUND |
| `alg: HS256` | blank/empty | admin | 404 NOT_FOUND |
| `alg: HS256` + `kid: none` | `.` | admin | 404 NOT_FOUND |
| `alg: HS256` + `crit: ["exp"]` | HMAC("x") | admin | 404 NOT_FOUND |

## Payloads Tested
```json
{"typ": "admin", "id": "00000000000000000000000000000001", "slug": "storm",
 "e": "admin@stormapplications.com", "ip": "127.0.0.1",
 "iat": 1787549620, "exp": 1793000000, "iss": "StorMApps"}

{"typ": "user", ...}
{"typ": "auth", ...}
```

## Endpoint Tested
`GET /auth/me` — baseline response for invalid tokens is `404 NOT_FOUND`

## Conclusion
**NOT CONFIRMED.** The JWT validation library in use by the Discloud/Caddy backend properly rejects unsigned tokens. All 25+ variants of the "none" algorithm attack returned 404. The server does not have the `none` algorithm vulnerability.
