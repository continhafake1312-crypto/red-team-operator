# F-030: Cred-Stuffing via /auth/login

**Date**: 2026-08-23
**Analyst**: Webapp Specialist
**Target**: `api-beta.stormapplications.com/auth/login`
**Severity**: 🟡 MEDIUM (No successful matches)

## Summary

Credential stuffing was attempted against the `/auth/login` endpoint with Turnstile bypass. All 27 combinations returned `FORBIDDEN` — no credentials valid.

## Methodology

1. Obtain fresh Turnstile token via 2Captcha (1 token per attempt)
2. POST to `https://api-beta.stormapplications.com/auth/login` (no Bearer header)
3. JSON body: `{"email":"...","password":"...","turnstile_token":"<TOKEN>"}`
4. Response analysis

## Results

All 27 combinations returned:
```json
{"code":"FORBIDDEN"}
```

Also confirmed via `/auth/email` that all 3 OSINT emails **do not exist** on the platform (return `USER_NOT_FOUND`).

## Analysis

The `/auth/login` endpoint:
- With `Authorization: Bearer test` → returns `NOT_FOUND` (incorrect routing)
- Without `Authorization` + valid Turnstile → returns `FORBIDDEN` (incorrect credentials or email not registered)
- The platform requires Discord OAuth for account creation — email/password login only works for existing accounts that have already linked Discord via OAuth

## Recommendation

- Obtain registered emails via `/auth/email` oracle (returns `USER_NOT_FOUND` vs other responses)
- Emails from common Brazilian providers (@gmail.com, @outlook.com, @uol.com.br) — but these are Discord bot customers, not company employees
- Primary attack vector: Discord OAuth exploitation or leaked storm_tokens
