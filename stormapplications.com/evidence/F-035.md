## Customer ID Manipulation
Storefront JWT has customer ID `01a032429a2f7438a499272015f0fee7`. Attempts to guess adjacent IDs via hex increment/decrement were not tested because:
- The server validates JWT signatures (none attack failed)
- Without the signing key, we cannot forge tokens with modified IDs
- The real token only works for public endpoints

## Conclusion
**NOT CONFIRMED.** The storefront slug is validated against the database — only existing storefronts (slug: `storm`) return data. The `/public/storefront/storm` endpoint is public (no auth required), so even non-authenticated users can access it. Protected endpoints (auth, carts, admin) require valid JWT authentication with proper scope.
