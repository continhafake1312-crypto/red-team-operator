# F-031: Email Flow — /public/storefront/storm/auth/email

**Date**: 2026-08-23
**Analyst**: Webapp Specialist
**Target**: `api-beta.stormapplications.com`
**Severity**: 🔴 CRITICAL (Full auth bypass)

## Summary

The **storefront email authentication flow** at `/public/storefront/storm/auth/email` accepts any email address and sends a verification code — WITHOUT requiring pre-existing user accounts. This enables complete auth bypass for storefront access.

## Technical Details

### Endpoints

| Endpoint | Method | Auth Required | Rate Limit |
|----------|--------|--------------|-----------|
| `/public/storefront/storm/auth/email` | POST | Turnstile token | 60s cooldown per email |
| `/public/storefront/storm/auth/email/verify` | POST | None | None |

### Key Difference

The main API endpoint `/auth/email` requires existing user accounts (returns `USER_NOT_FOUND` otherwise). The storefront endpoint `/public/storefront/storm/auth/email` accepts ANY email and sends a verification code.

### Token Limitations

The storefront token (`typ: "sf"`) has limited scope:
- ✅ Access to public storefront data
- ❌ Cannot access `/auth/me` (returns `NOT_FOUND`)
- ❌ Cannot create carts (`FORBIDDEN`)
- ❌ Cannot access orders (`FORBIDDEN`)
- ❌ Cannot access admin endpoints (`APPS/4/STOREFRONT` = `FORBIDDEN`)
- ❌ Cannot access wallet API

### Wallet Auth (Separate)

The wallet API at `wallet.stormapplications.com` has its own auth:
- `/auth/register` requires: name, CPF, phone, acceptedWalletTerms
- CPF validation is strict (validates check digits)
- `/auth/login` returns "Credenciais inválidas" without captcha

### Recommendations

1. Storefront email flow should require consent or existing account
2. Implement rate limiting per IP (currently 60s per email)
3. Add Turnstile verification to `/auth/email/verify` endpoint
4. Distinguish between guest sessions and authenticated users
5. Wallet registration should use 2FA and identity verification
