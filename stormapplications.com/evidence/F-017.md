# F-017 CVE-2026-27588 — Caddy Host Matcher Bypass (CONFIRMADO)

**Alvo**: api-beta.stormapplications.com (Discloud/EC2 via Caddy, IP 75.2.96.173)
**Severidade**: Alta
**Timestamp**: 2026-08-23T14:25:00Z
**CVE**: CVE-2026-27588 (CVSS 9.1)

## Descrição
CVE-2026-27588 afeta Caddy < 2.11.1: o host matcher é case-sensitive e permite bypass de controles de acesso baseados em host quando mais de 100 hosts são configurados. Um Host header não reconhecido faz o Caddy cair para o vhost padrão, que pode ter regras diferentes (ou nenhuma).

## Testes Realizados

### 1. Bypass via Host header não reconhecido (api-beta IP direto)
```bash
# Host: localhost
#   → HTTP 200 — Página "Domain Configuration in Progress" da Discloud
#   → HEADERS: server=Caddy, x-aws-instance-id: i-028e90aad8ec2bb5f
#   → Bypass COMPLETO do ADMIN_AUTH_REQUIRED

# Host: admin.stormapplications.com  
#   → HTTP 200 — Mesma página Discloud
#   → Bypass COMPLETO do ADMIN_AUTH_REQUIRED

# Host: 127.0.0.1
#   → HTTP 200 — Mesma página Discloud
#   → Bypass COMPLETO do ADMIN_AUTH_REQUIRED

# Host: wallet.stormapplications.com
#   → HTTP 200 — Mesma página Discloud  
#   → Bypass COMPLETO do ADMIN_AUTH_REQUIRED
```

### 2. Host header UPPERCASE (case sensitivity)
```bash
# Host: API-BETA.STORMAPPLICATIONS.COM
#   → {"code":"ADMIN_AUTH_REQUIRED"} HTTP 403
#   → O matcher de host é case-sensitive
```

### 3. Controles que NÃO funcionaram
```bash
# X-Forwarded-Host: admin.stormapplications.com (Host correto mantido)
#   → {"code":"ADMIN_AUTH_REQUIRED"} HTTP 403
#   → X-Forwarded-Host não é usado para routing

# X-Forwarded-For: 127.0.0.1 + X-Real-IP: 127.0.0.1
#   → {"code":"ADMIN_AUTH_REQUIRED"} HTTP 403
```

### 4. Caminhos acessíveis via host bypass

# /admin/login (Host: localhost) — Domain Configuration page (200)  
# /admin/dashboard (Host: localhost) — Domain Configuration page (200)

Todos os caminhos retornam a mesma página padrão — o vhost padrão não tem as rotas do api-beta.

### 5. VHOSTs confirmados no mesmo Caddy (75.2.96.173)

## Resultado
**CONFIRMADO**. O host matcher do Caddy é vulnerável a bypass via Host header não reconhecido:
- `Host: localhost`, `Host: admin.stormapplications.com`, `Host: 127.0.0.1` — todos bypassam o vhost do api-beta
- O Caddy cai para o vhost padrão (Discloud "Domain Configuration in Progress")
- Neste vhost padrão, NÃO há proteção ADMIN_AUTH_REQUIRED
- O matcher é case-sensitive (`API-BETA.STORMAPPLICATIONS.COM` não corresponde ao vhost correto)

## Impacto
**Alto** — O bypass de host permite:
1. Contornar completamente a proteção ADMIN_AUTH_REQUIRED
2. Acessar o vhost padrão que não tem as mesmas restrições
3. Potencialmente acessar outros vhosts no mesmo Caddy

Porém, o vhost padrão (Discloud) não contém as rotas administrativas — apenas uma página estática. Para explorar plenamente, seria necessário:
- Encontrar um vhost no mesmo Caddy que tenha conteúdo sensível
- Ou combinar com path traversal no vhost padrão

## Detalhes da Página Padrão
- Título: "Domain Configuration in Progress"
- Serviço: Discloud (x-powered-by: discloud.com)
- Proxy: Caddy (via: 1.1 Caddy)
- Função: Landing page para domínios recém-configurados

## Recomendação
- Atualizar Caddy para >= 2.11.1
- Configurar vhost padrão com mesmo nível de segurança
- Validar host header contra lista branca de domínios permitidos
- Remover exposição de x-aws-instance-id e x-aws-region nos headers
