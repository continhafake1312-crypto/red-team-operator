# F-012 Handlebars SSTI via {{{guild.*}}} Triple-Stash
Alvo: mng.stormapplications.com/api/login
Severidade: Alta (XSS via raw HTML template)
Timestamp: 2026-08-23T05:20:00Z

## Descrição
O endpoint GET /api/login renderiza um template Handlebars com variáveis
triple-stash `{{{guild.*}}}` (raw HTML, sem escaping):
- `{{{guild.banner}}}` — URL da imagem do banner
- `{{{guild.icon_url}}}` — URL do ícone do servidor
- `{{{guild.name}}}` — nome do servidor

Triple-stash {{{ }}} no Handlebars NÃO faz HTML-escape, diferentemente de
{{ }} que faz escape.

## Testes realizados
```bash
# GET sem parâmetros — página de erro Handlebars
curl -sk "https://mng.stormapplications.com/api/login" \
  -H "Authorization: Bearer test"

# SSTI via state parameter (injeção de template)
curl -sk "https://mng.stormapplications.com/api/login?state=%7B%7B7*7%7D%7D%20test"

# SSTI via triple-stache
curl "https://mng.stormapplications.com/api/login?state=%7B%7B%7B7*7%7D%7D%7D%20test"
```

## Resultados
- Valores `{{{guild.*}}}` vêm da API do Discord (não de input do usuário)
- State parameter é URL-encoded na redirect, NÃO avaliado como template
- SSTI não confirmada diretamente — variáveis do template são do Discord API
- Porém, se QUALQUER input do usuário fluir pro contexto do Handlebars, SSTI é possível

## Impacto
- **XSS potencial**: se `guild.name` ou `guild.banner` forem controláveis
  (via servidor Discord malicioso), {{{ }}} permite injeção de HTML/JS.
- **SSTI potencial**: se algum parâmetro do usuário (state, código, etc.)
  for passado pro template sem sanitização, RCE é possível via Handlebars helpers.
- CVE-2019-19919 (Handlebars Prototype Pollution → RCE) é aplicável se SSTI for confirmada.

## Recomendação
- Mudar de {{{ }}} para {{ }} (com escape)
- Validar/sanitizar todos os dados que entram no contexto do template
- Não usar Handlebars se possível (migrar para template engine mais seguro)
