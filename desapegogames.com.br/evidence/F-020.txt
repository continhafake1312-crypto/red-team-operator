# F-020 — CodeIgniter 3.x confirmado + CSRF protection OFF (CVE-2024-41344 pré-cond) [ALTO]

**Host:** `desapegogames.com.br` (via bypass CF `186.226.60.54`)
**Severidade:** ALTO
**Status:** CONFIRMADO
**Data:** 2026-09-05T00:24Z (UTC)
**OWASP:** A01:2021 — Broken Access Control (CSRF); A06:2021 — Vulnerable & Outdated Components (CI 3.x)

## Descrição

A aplicação roda **CodeIgniter 3.x** (provavelmente 3.1.13, última 3.x,
EOL desde 2024) e tem **`csrf_protection` DESLIGADO** (csrf_regenerate
implicitamente off). Os dois juntos satisfazem as pré-condições do
**CVE-2024-41344** (CSRF → trocar senha de admin, CVSS 7.5) e deixam
todos os endpoints state-changing vulneráveis a CSRF.

### CodeIgniter 3.x confirmado — evidências
- **Página de erro canônica do CI 3**: `GET /index.php/anuncio/'` retorna
  o template de erro padrão do CI 3 (`::selection { background-color:
  #E13300; }`, `#D0D0D0`, `#002166`, `<h1>An Error Was Encountered</h1>`,
  `<p>The URI you submitted has disallowed characters.</p>`). Esse
  template e essa mensagem são específicos do `system/core/URI.php`
  do CI 3 (função de validação `permit_uri_chars`). O CI 4 usa
  template diferente (Exception page "Whoops!").
- **Cookie `ci_session`** (32 chars, sha1-like, sem prefixo) — convenção
  do CI 3 (`Session` driver nativo).
- **Routing `index.php/`** ativo: `GET /index.php/` → 200 (front
  controller, 151898 bytes), `GET /index.php/welcome` → 301 (default
  controller removido mas routing exposto).
- **`URL_SUFFIX=.html`** em endpoints AJAX (`/busca.html`,
  `/notificacoes.html`, `/carrinho.html`, `/anuncio/perguntas.html`) —
  feature `url_suffix` do CI 3 (`config.php`).
- **Layout CI 3**: `/system/` → 403, `/application/config/production/
  database.php` → 403 (estrutura de dirs do CI 3).

### CSRF protection OFF — evidência
```bash
# POST /admin/autenticacao/login SEM CSRF token (e sem captcha) é PROCESSADO
curl -k -H "Host: desapegogames.com.br" --proxy socks5://127.0.0.1:9050 \
  -X POST https://186.226.60.54/admin/autenticacao/login \
  -d "login=admin&senha=WrongPassXyZ999"
# HTTP 200 — o server valida cred e captcha, MAS NÃO reclama de CSRF.
# Resposta: "O campo nome de usuário e senha não confere." +
#           "O campo captcha é obrigatório."
# Se csrf_protection=TRUE (CI 3 default), o POST sem token csrf_test_name
# seria rejeitado com "The action you have requested is not allowed."
# (erro CSRF do CI 3) ANTES de qualquer validação de cred.
```
O form `/admin/autenticacao/login` e `/cadastro` **não contêm** campo
`csrf_test_name` (nem hidden input) — confirma `csrf_protection=FALSE`
ou ausente na config.

## Reprodução
```bash
# 1) Confirmar CI 3 (erro canônico)
curl -k -H "Host: desapegogames.com.br" --proxy socks5://127.0.0.1:9050 \
  "https://186.226.60.54/index.php/anuncio/'"
# <h1>An Error Was Encountered</h1>
# <p>The URI you submitted has disallowed characters.</p>

# 2) Confirmar CSRF OFF (POST state-changing sem token é aceito)
curl -k -H "Host: desapegogames.com.br" --proxy socks5://127.0.0.1:9050 \
  -X POST https://186.226.60.54/admin/autenticacao/login -d "login=admin&senha=x"
# HTTP 200 — processa cred/captcha, sem erro de CSRF
```

## Impacto

1. **CVE-2024-41344 (CVSS 7.5) aplicável**: CSRF em CodeIgniter 3.1.13
   permite a atacantes forjar request de troca de senha de admin
   (privesc). Pré-condições satisfeitas:
   - App é CI 3.x (provavelmente 3.1.13, EOL).
   - `csrf_protection=FALSE` (confirmado).
   - Bypass CF via .54 (sem WAF/Referer/Origin check da CDN) facilita
     entregar o payload CSRF cross-origin.
   - Exige admin logado vítima acessar link/iframe crafted (vetor
     social/phishing do admin).
2. **CSRF geral em TODOS os endpoints state-changing**: `/cadastro`,
   `/login` (não seria afetado por CSRF em si), `/esqueceu-senha`
   (resetar senha de terceiro via CSRF?), `/anuncio/perguntas.html`
   (postar pergunta como vítima), `/painel/anuncios/cadastrar` (criar
   anúncio como vítima), `/admin/*` (ações admin como admin logado:
   aprovar saques, alterar comprovantes, gerenciar permissões). O
   atacante não precisa de cred — só que a vítima logada visite uma
   página com form/JS crafted.
3. **CI 3.x EOL**: sem patches de segurança. CVE-2022-40824..40835
   (SQLi em query builder, "disputed") podem ser aplicáveis se a app
   usar query builder com input do usuário (candidato: `/busca.html`
   `pesquisar` — em análise no sqlmap).
4. **Stack de erros**: a página de erro do CI 3 pode vazar info se
   `ENVIRONMENT` não for `production` (aqui é prod, mas paths internos
   expostos em /teste já).

## Recomendação

- **Migrar do CodeIgniter 3.x (EOL)** para CI 4.x (mantido) ou framework
  moderno (Laravel/Symfony). CI 3 não recebe mais patches de segurança.
- **Habilitar `csrf_protection=TRUE`** em `application/config/config.php`
  e regenerar tokens (`csrf_regenerate`). Adicionar `csrf_test_name` em
  todos os forms state-changing. Validar `Origin`/`Referer`.
- **Adicionar proteção CSRF específica** no `/admin/*` (SameSite=Strict
  no cookie `ci_session`, que hoje é só `secure; HttpOnly` sem SameSite).
- **Restringir origem** (F-001) — sem bypass CF, o WAF ajudaria a
  filtrar requests cross-origin.
- Patch/workaround do CVE-2024-41344: ver issue upstream do CI 3.
