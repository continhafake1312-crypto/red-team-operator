# F-020 — Pure-FTPd: banner suprime versão, anonymous DESABILITADO, MLSD/TLS presentes

**Host:** 186.226.60.53 / .54 / .56 (porta 21 TCP)
**Serviço:** Pure-FTPd [privsep] [TLS] (build DirectAdmin, versão SUPRIMIDA)
**Severidade:** BAIXO (info disclosure limitado; anonymous negado; cred stuffing falhou)
**Status:** VALIDADO — anonymous negado, versão não confirmável, MLSD presente (trigger CVE-2024-48208 disponível se versão ≤1.0.51)
**Operador:** exploit | **Data:** 2026-09-05T00:08Z

## Reprodução (não-destrutiva)

### Banner — versão SUPRIMIDA

```bash
$ proxychains4 -q nc -w 10 186.226.60.54 21 < /dev/null
220---------- Welcome to Pure-FTPd [privsep] [TLS] ----------
220-You are user number 1 of 50 allowed.
220-Local time is now 21:06. Server port: 21.
220-This is a private system - No anonymous login
```

Observações:
- Banner **não revela versão** (apenas "Pure-FTPd [privsep] [TLS]") —
  configuração `DisplayDotFiles no` + banner customizado DirectAdmin.
- **Anonymous login DESABILITADO** explícito: "No anonymous login".
- privsep (privilege separation) ativo. TLS suportado.
- Max 50 conexões, idle 15min — rate limit presente.

### Oracle de login (anti-enum na fase USER)

```
> USER zzznonexistent999
< 331 User zzznonexistent999 OK. Password required   # NÃO diferencia user válido/inválido
> PASS wrong
< 530 Login authentication failed                     # falha só na fase PASS
```

Anti-enum: responde `331 OK. Password required` para qualquer USER (válido ou
inválido). Diferenciação só ocorre no PASS (`530`). Não permite enumerar
usuários via FTP (timing attack ainda possível mas não testado — OPSEC).

Nenhuma cred default/relacionada ao domínio funcionou. Sem lockout detectado.

## Impacto

- **Anonymous FTP:** NÃO (desabilitado explicitamente). Sem acesso não-autenticado.
- **Versão não confirmável:** banner suprime → CVE-2024-48208 (≤1.0.51) e
  CVE-2019-20176/2020-9365/9274/2021-40524 (se =1.0.49) permanecem CONDICIONAIS.
  MLSD/MLST presentes (trigger disponível) — se versão vulnerável + cred FTP
  obtida por outro vetor, explorável.
- **Cred stuffing:** sem wordlist de breach, baixa probabilidade. Default e
  senhas relacionadas ao domínio falharam.
- **TLS:** protege creds (sem sniffing).

## Recomendação

- Manter anonymous desabilitado (já configurado).
- Confirmar versão Pure-FTPd internamente; se ≤1.0.51, atualizar para 1.0.52
  (CVE-2024-48208). Se =1.0.49, urgente (5 CVEs).
- Adicionar fail2ban na porta 21 (cred stuffing).
- O login via USER não enumera (bom); manter.

## Notas

- Cred stuffing feito com delay 15s, 5 tentativas, sem persistência. Não
  houve bloqueio (fail2ban aparentemente não ativo no FTP, ou threshold
  não atingido).
- A versão exata do Pure-FTPd só é confirmável com foothold (pacote
  instalado, `pure-ftpd --version` ou binário).
