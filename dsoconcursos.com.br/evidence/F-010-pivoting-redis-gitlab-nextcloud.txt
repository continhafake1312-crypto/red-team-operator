## Impacto
- **Redis interno**: acesso a sessões Nextcloud (ATO potencial), job queue Redash
  (queries/BI), job store MCP (contexto de IA com tokens).
- **GitLab PAT**: acesso ao container registry + criação de runners → supply chain
  attack (push imagem maliciosa) + RCE via CI runners.
- **Nextcloud**: acessível do foothold (bypass CF) — creds pendentes, mas session
  hijack e brute-force são viáveis com timing/proxy adequados.
- **Docker registry**: acessível mas formato custom (Magalu CR).

## Recomendação
- Isolar o container MCP da rede interna (VPC peering/VPN) — não deveria alcançar Redis/GitLab.
- Rotacionar Redis password + GitLab PAT.
- Configurar Nextcloud brute-force protection com TTL mais longo.
- Mover Docker registry para auth via OAuth/JWT (não Basic com CI creds).

## Próximo passo
- Tentar Nextcloud login com timing cuidadoso (1 tentativa a cada 60s, evita 429).
- Push de imagem Docker maliciosa no registry GitLab (se deploy automático).
- Enumerar Redash data_source:schema (queries de BI financeiro).
