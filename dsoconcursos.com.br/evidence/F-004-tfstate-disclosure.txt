# F-004 Terraform state exposto em bucket S3 — disclosure de topologia de infra
Alvo: dsoconcursos.com.br — bucket dso-tfstate-prod (Magalu Cloud Objects)
Severidade: ALTA (CVSS 7.5)
Timestamp: 2026-08-27T05:42:00Z

## Reprodução (verificação independente do coordenador, via Tor)
```
$ aws --endpoint-url https://br-se1.magaluobjects.com s3 ls s3://dso-tfstate-prod --recursive
2026-08-24 19:46:55  130250  environments/prod/terraform.tfstate
$ aws s3 cp s3://dso-tfstate-prod/environments/prod/terraform.tfstate -   (130KB, 70 recursos)
```
Artefato: `recon/active/tfstate_prod.json`

## Impacto
- Mapeamento completo da infra interna (IPs, SGs, portas, IDs) → facilita pivoting
  interno via bastion/edge se foothold obtido.
- Confirma que o PostgreSQL de produção (201.23.74.56) está fora da VPC Magalu
  (host separado, possivelmente outro provider) — explica exposição à internet.
- Docker daemon (2375) exposto internamente no CI runner → RCE interno se pivot.
- Tailscale (41641) aberto → possível vetor de acesso mgmt se chave Tailscale vazada.

## Recomendação
- Mover terraform.tfstate para bucket privado (sem acesso público/key genérica);
  usar remote state com lock + encryption (S3 + KMS + IAM restrito).
- Habilitar `sensitive = true` em outputs/attrs que exponham IPs internos.
- Restringir SG do Docker (2375) a apenas o necessário; preferir TLS + auth.

## Próximo passo

- Buscar chave Tailscale nos secrets vazados (service-keys.env) para acesso mgmt.
