## Interpretação
A identidade real de um desenvolvedor (`daviscardi1@gmail.com` / "YangDV") foi
obtida por OSINT em commits públicos do GitHub. Não há infra de email própria
no domínio (sem MX/TXT/SPF/DMARC) — comunicação provável via Discord. O email
é um **lead direto para credential-stuffing** contra o fluxo de login do alvo
(`/api/auth/login` email/senha + Turnstile — bypass do Turnstile via 2Captcha,
ver F-018): se o dev reutilizou a senha em uma breach pública, a conta (que
pode ser admin/dev no alvo — user id=1 "Yang" é admin, ver F-014) seria
comprometida. Não foi realizado credential-stuffing neste engagement (sem
API key HIBP/leak-lookup e fora do escopo autorizado de teste de credenciais
reais), mas o lead está documentado.

## Impacto
- Vetor de credential-stuffing contra a conta admin/dev (`Yang`, user id=1,
  role:admin — confirmado em F-014) se a senha do email estiver em breaches
  públicas e for reutilizada no alvo.
- Phishing direcionado (identidade + Discord) contra o dev.
- Sem confirmação de comprometimento (não testado — fora do escopo).

## Recomendação
- Forçar 2FA (TOTP/SMS — componente `Sms` já existe no bundle) para contas
  admin/staff; proibir login só com senha para roles privilegiadas.
- Verificar `daviscardi1@gmail.com` em HIBP internamente; forçar reset se
  comprometido.
- Remover a associação do email real de commits públicos (usar noreply).
- Rate-limitar `/api/auth/login` por email/IP e bloquear senhas em breaches
  (k-anonymity / HIBP API na troca de senha).
